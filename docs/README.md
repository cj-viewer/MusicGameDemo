# 文档索引与维护约定

本文档是仓库内 Markdown 的入口。先按用途选择文件，不要把长期设计、当前可运行规则和历史记录混为一谈。

## 文档分层

| 文件 / 目录 | 事实来源 | 何时更新 |
|---|---|---|
| [简化玩法策划案（原型版）](简化玩法策划案（原型版）.md) | 当前玩家可体验的原型规则 | 修改操作、敌人、数值、波次、掉落或验收范围时 |
| [实机落地与调整记录](实机落地与调整记录.md) | 当前代码参数、代码落点、验收清单和完整改动账本 | 所有玩法、素材、表现、工程或部署改动 |
| [2D 音乐弹幕游戏策划案](<2D音乐弹幕游戏策划案 (持续更新).md>) | 长期设计目标与视觉参考 | 修改未来产品目标、关卡或叙事方案时 |
| [更新记录/](更新记录/README.md) | 按日期的短变更说明 | 每个可交付改动都要新增或更新 |
| [资源与素材规范](资源与素材规范.md) | 运行时资源与策划附件的边界 | 新增、迁移或删除素材时 |
| [根目录 AGENTS.md](../AGENTS.md) | Agent 的必读入口、变更合同和验证要求 | 新 Agent 进入仓库或变更流程时 |
| `图片和附件/` | 完整策划案引用的视觉参考 | 仅随引用它们的策划内容更新 |

## 同次改动的最小文档集合

| 改动类型 | 必须同步维护 |
|---|---|
| 玩法、数值、输入、敌人、动画、音效 | 更新记录 + 实机落地记录；玩家可感知时再更新简化策划案 |
| 新增 / 迁移 / 删除运行时素材 | 更新记录 + 实机落地记录 + 资源规范；必要时改 preload / 动画注册 |
| 长期关卡、Boss、剧情或美术方向 | 完整策划案；若已经实装，再补前两项 |
| 部署、分支、构建或目录结构 | 更新记录 + 实机落地记录 + 根 README |

## 清理原则

- 不删除仍被 Markdown 引用的 `图片和附件/` 文件。
- 不因为“和当前原型不一致”就删除完整策划案中的未来设计；应明确标注为未实现。
- `.claude/skills/` 与 `.agents/skills/` 是不同 agent 入口的同步副本，不作为游戏策划文档清理对象。
- 删除任何文档或素材前，先确认代码、Markdown 与部署产物均无引用；Git 历史不是跳过引用检查的理由。
