# 资源与素材规范

## 目录边界

| 内容 | 目录 | 是否参与构建 |
|---|---|---|
| 角色、武器、特效、背景、UI | `public/assets/images/` | 是 |
| BGM、音效 | `public/assets/audio/` | 是 |
| 开场视频 | `public/assets/video/` | 是 |
| 字体、谱面、关卡数据 | `public/assets/fonts/`、`public/assets/data/` | 是 |
| 策划参考图、原图、附件 | `docs/图片和附件/` | 否 |

运行时代码只可从 `public/assets/` 加载资源。Phaser 路径必须通过 `import.meta.env.BASE_URL` 拼接，不能写死 `/assets/`，以兼容 GitHub Pages 的仓库子路径。

`bg1.psd` 等 Photoshop 文件属于制作源，不是浏览器运行时资源。第一关当前制作源为项目方提供的 `1920 x 1080`、8-bit RGB `bg1.psd`，SHA-256 为 `D4748A87419E2D04FC83015CE5CA5750D95754802942CF39FE599903CDD20B60`；运行时只加载从中导出的 PNG。环境-only 合成覆盖 `images/backgrounds/pond-stage/pond-stage-background.png`，UI、PSD 隐藏层和已拆出的 `Rock` 前景不得重复烘焙进该底图。当前运行时逻辑画布为 `2560 x 1440`；PSD 导出的布局仍以原始 `1920 x 1080` 坐标为权威源，在 `MainScene` 中统一乘 `4 / 3` 等比映射，不得反向改写制作源规格。

## 角色序列帧

当前玩家与角色特效的正式制作依据为飞书知识库 [Si想家-角色特效规范](https://lilithgames.feishu.cn/wiki/N1fTwofxXiMNs2k8H8VcTX9jnnd?from=from_copylink)（Docx revision `750`，复核于 `2026-08-15`）。其中明确要求：制作基准分辨率 `1920 x 1080`、像素图使用 Nearest Neighbor、角色与特效帧为 `256 x 256px`、棍状武器为 `128 x 128px`，玩家棍状武器层级为“武器 > 角色 > 特效”。本地运行时逻辑画布已升级到 `2560 x 1440`，但源文件画布规格不变；为维持既有相对屏幕占比，角色、特效与武器只调整运行时显示倍率，不得重采样或改写制作源。

角色素材默认只绘制**朝右**版本；向左运动由 Phaser 的 `setFlipX(true)` 完成。

```text
# 正式玩家（历史上已有 animation 层，保留不动）
public/assets/images/characters/player/animation/<动作>/player_<动作>_<两位序号>.png

# 正式 NPC（回滚 90b3adc 的目录分类后，动作直接位于角色根目录）
public/assets/images/characters/npc/<角色>/<动作>/<角色>_<动作>_<两位序号>.png
```

示例：

```text
public/assets/images/characters/player/animation/run/player_run_01.png
public/assets/images/characters/player/animation/dash/player_dash_01.png
public/assets/images/characters/npc/npc_guard01/idle/npc_guard01_idle_01.png
```

- 只把实际播放的帧提交进运行时目录；站定测试帧、重复帧和废弃导出帧应在导入时清掉。
- **先校准，再接入引擎。** 导入前必须逐帧检查透明内容边界、脚底基线和像素高度；不得根据完整画布大小直接设置统一显示尺寸。
- 以一个动作作为视觉基准，同一动作的所有帧必须检查透明内容边界和脚底基线；宽度按原比例变化，不得为统一宽高而拉伸。
- 不同动作可以使用不同内容高度。旧粉丝可变画布的跑步 / 翻滚 / 近战校准值只属于历史素材，不得继续套用到正式 `npc_fan01` 的 `256 x 256px` 方形帧。
- 正式红发玩家素材统一使用 `256 x 256px` 透明画布：Idle 8 帧、Run 8 帧、Dash 12 帧、Attack Light / Hard 各 5 帧、Death1 / Death2 各 8 帧。Attack Light / Hard PNG 是纯特效层，只能用一个独立 Sprite 显示，不得替换本体纹理或另建放大副本；特效必须与角色画布同中心、同翻转并在播放期间跟随角色，深度低于武器和角色。当前 Light 三张代表帧的非透明像素均只有 `Alpha=255`，Hard 代表帧含 `246` 档 Alpha；运行时分别使用亮黄 `#fff36b` / 紫粉 `#f28cff` 填色、`0.82 / 0.86` 整体 Alpha，并由同一 Sprite 使用 `NORMAL` 实色合成，只在外沿使用 Glow 与 Threshold→Blur→ADD Bloom。Light 继续使用角色基准尺寸，Hard 继续使用角色基准的 `1.18x`，本轮不改变既有大小。预览 GIF 仅是角色与特效的合成预览。轻攻击输入只播放 Attack Light，重攻击输入只播放 Attack Hard，错误输入也按实际按键选择表现。
- 短时攻击 Sprite 采用 `NORMAL` 实色主体配低强度 Glow 与 Threshold→Blur→ADD Bloom，不得把整张主体改成 ADD。玩家 Light / Hard 的 Glow strength 为 `0.22`、Inner strength 为 `0.04`、Bloom amount 为 `0.06`；保安 / 粉丝分别为 `0.20 / 0.03 / 0.05` 与 `0.22 / 0.04 / 0.055`；公共 Blur strength 为 `0.20`，保安 / 粉丝 Sprite Alpha 为 `0.82 / 0.84`。程序线弹和点弹不使用上述多对象合成：玩家普通 / 踩拍各使用一张 `128 x 64` RGB+Alpha CanvasTexture，外壳 / 中层 / 核心颜色分别为 `#d92f3d / #ff6470 / #fff6f3` 与 `#d92f3d / #ff7a82 / #fffff7`；外壳长度由判定段 `1.35x` 缩短 `20%` 为 `1.08x`，厚度仍为原弹体 `0.52x`，中层为外壳 `90% / 82%`、核心为 `76% / 54%`，纹理柔光峰值 Alpha `0.24`、sigma `2.6px`。保安点弹为 `#18b6cf / #7ff7ff / #f2ffff`，粉丝点弹为 `#d92c16 / #ff7832 / #fff6cf`；中层 / 核心半径为外球 `82% / 56%`，柔光峰值 Alpha `0.24`、sigma `2.4px`。每颗程序弹只能显示一个无 Tint 的 `NORMAL` Image，核心、过渡、外壳和柔光全部烘入同一纹理；不得另叠 ADD 光层。线弹缩短时必须锁住既有尾端锚点，并通过独立 FPV 显示宽度同步短线；外部纹理包围、透明物理宿主、判定、速度和时序保持既有值，Sprite 滤镜的 Glow 距离、Blur 半径与 Threshold 保持既有值。
- `2560 x 1440` 内部画布中，玩家本体与 Light 特效基准按约 `0.9422x` 显示，可见内容高约 `101.76px`，固定受击体约 `39.57 x 101.76px`；Hard 特效在此基础上乘 `1.18`。FIT 到 1080p / 旧 720p 窗口时，可见内容高分别约为 `76.32px / 50.88px`，用于维持升级前的相对屏幕视觉大小。不得擅自把玩家本体改为原生 `1x`。
- 玩家正式手持贴图固定使用 `images/weapons/light_stick/player/light_stick_player.png` 与 `images/weapons/baton/player/baton_player01.png`，源图必须为 `128 x 128px`。当前 2K 运行时显示比例约 `0.7538x`；旋转原点必须使用透明内容的握把末端，荧光棒为 `(101/128, 98/128)`、警棍为 `(123/128, 121/128)`。原点固定在角色腰部中线、内部下移 `30px`（FIT 到 1080p / 旧 720p 窗口等效 `22.5px / 15px`）。非中心 Origin 禁止用 Phaser `flipX` 翻 UV；另一朝向必须保持 `flipX=false`，改用负 `scaleX` 围绕 Origin 做几何镜像，并同步反转挥击角。绘制深度必须略高于所属玩家，玩家层级由前到后为“武器 > 角色 > 特效”；不得再用程序矩形棒替代。
- 当前正式资源目录没有截图中展示的 Pick 序列帧。不得用 Attack、Dash 或 Idle 冒充 Pick；补齐素材后再同步更新 preload、状态机、资源验收和文档。
- 已核对现有 54 张玩家动画 / 特效 PNG 均为 `256 x 256px`，两张玩家正式武器及其 8 个候选 PNG 均为 `128 x 128px`。
- 正式橙色粉丝运行时使用 `images/characters/npc/npc_fan01/run/` 的 8 张 `256 x 256px` 帧；第 4 拍攻击使用 `attack_hard/` 的 `02–07` 共 6 张透明特效帧；专属武器为 `images/weapons/light_stick/npc_fan01/light_stick_fan01.png`（`128 x 128px`）。由于画布规格与玩家一致，粉丝本体必须复用玩家本体约 `0.9422x` 的 2K 运行时倍率，粉丝武器必须复用玩家武器约 `0.7538x` 的倍率，不得套用程序化世界物件倍率。Hard 特效六帧必须由场景时钟在 `500ms` 内手动切换贴图，不得注册或调用 Phaser Animation `.play()`；当前引擎版本在该独立特效首次播放时会锁住主线程。运行时层级必须为“角色 > 武器 > 特效”，特效主体使用 `NORMAL` 橙红实色填充，只有低强度外沿 Glow / Bloom 使用 ADD。仓库中的旧 `images/characters/fan/` 素材不再由 `FanEnemy` 加载，仅保留历史来源，不得与正式帧混用。完整归类、数量和运行时索引见 [美术资产索引](美术资产索引.md)。
- 每个动作完成裁切和缩放后，至少目视检查一张基准帧和一张幅度最大的帧，确认脚底不跳、攻击不显小、透明边缘不影响比例。
- 新动作必须同时更新 `preload`、运行时帧推进路径、敌人/角色状态切换和更新记录；循环角色本体通常注册 Phaser Animation，已记录存在引擎锁死风险的独立特效必须使用项目指定的安全帧调度方式。
- 保持透明背景，单帧建议不超过 `1MB`。

## 粉紫音乐广场分层验收

- 权威颜色源为 `docs/图片和附件/pink-stage-reference.jpg`（`1920 x 1080`、sRGB）；生成模型只能辅助制作 `pink-stage-segmentation-matte.png` 灰度蒙版，不得重绘或重新调色最终物件。
- `pink-stage-clean-background.png` 是不带物件的干净交付底图；`pink-stage-runtime-base.png` 是正式关重组时使用的局部色调衔接底图。两者都必须为 `1920 x 1080`，运行时代码加载后不得附加 tint、滤镜或非正常混合模式。
- `images/environment/pink-stage/objects/` 固定保留 35 张 RGBA PNG。每张可见 RGB 必须逐像素来自参考原图；Alpha 除主体外必须覆盖原图中的接触影与投影，并为边缘留出透明安全区。
- `object-11-entrance-gate.png` 必须整体保留安检口开口内的左侧设备 / 人影、中央淡色场景、右侧设备 / 标牌，以及前排栏杆和中央雕像；不能把开口误当成需要清空的背景。
- `object-37 / 38 / 39` 分别覆盖底部左右灌木与中央低墙；最终原图坐标为 `(0,847,861,233)`、`(1091,847,829,233)`、`(812,994,313,85)`，必须连续覆盖至画布侧边和底边。
- `scripts/rebuild_pink_stage_layers.py` 是分层资源的可重复生成入口；脚本必须同步输出 35 张物件和 `src/game/pinkStageProps.generated.ts`，不得手工改生成坐标表。
- 验收至少包括：35 张文件均为 RGBA 且存在非零 Alpha；可见 RGB 对参考原图的逐像素误差为 `0`；离线重组全画面平均绝对色差不高于 `1 / 255`；浏览器内入口细节、长阴影、底部三块与参考色调一致且资源无 404。

## 编码与体积规范

远端部署的首屏体验直接由这些约束决定，导入素材时必须逐条确认：

- **BGM 必须是真 MP3**，禁止用 `.mp3` 扩展名承载 FLAC / WAV 等无损格式。导入前用 `ffprobe -show_entries stream=codec_name` 核对；目标码率约 `190kbps` VBR（`ffmpeg -vn -c:a libmp3lame -q:a 2`），并用 `-vn` 剥离封面图。
- **重编码 BGM 后必须校验节拍未偏移**：把新旧文件解码为同采样率 PCM 做互相关，确认对齐偏移为 `0` 样本、样本总数一致；若有偏移，必须同步修正 `src/game/bgmTracks.ts` 中该曲目的 `firstBeatOffset`，否则正式关卡会偏拍。
- **两段片头视频**片源分辨率均固定不超过 `1920 x 1080`；当前 `2560 x 1440` 逻辑画布只负责等比显示，更高片源分辨率只会浪费码率，不会提升现有素材清晰度。视频使用 H.264 + AAC，CRF 约 `23`。当前播放顺序为 `intro.mp4 → intro-rocket.mp4 → 教学`。
- **每一段片头视频的 `moov` 原子都必须前置**：编码时加 `-movflags +faststart`；对已有文件可执行 `node scripts/faststart-mp4.mjs <文件>` 无损前移。`moov` 在尾部时浏览器必须下完整个文件才能起播。
- **新资源必须归入明确的加载分层**：进教学关前必须创建的游戏内纹理走 `queueCoreAssets()`，正式关卡 BGM 走 `queueDeferredBgm()`；不得直接写回 `MainScene.preload()`。当前 core 清单精确为 `164` 个 Loader 项：`161` 张图片、两条节拍音效与教学 BGM `bgm0.mp3`；图片中包含 37 张环境运行资源与 8 张教学 UI。`bg1.psd`、`pink-stage-clean-background.png`、10 张演唱会候选图和未加载的上游 `main-menu.png` 不进入 preload；当前开场标题图与两段片头只由 `IntroScene` 单独加载，也不计入 core。
- 导入后必须重新统计进教学关前的下载总量。当前 `queueCoreAssets()` 图片文件合计 `9,707,694` 字节，3 条音频合计 `3,649,699` 字节，总计 `13,357,393` 字节（约 `12.74MiB`）；37 张环境请求的统计口径不包含 UI，两段片头视频也不计入 core。不得把制作源或未加载候选图计入浏览器阻塞量，也不得因新增资源绕过片头预热或重新同步阻塞其余三首 BGM。
