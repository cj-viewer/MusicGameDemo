# 资源与素材规范

## 目录边界

| 内容 | 目录 | 是否参与构建 |
|---|---|---|
| 角色、武器、特效、背景、UI | `public/assets/images/` | 是 |
| BGM、音效 | `public/assets/audio/` | 是 |
| 开场视频 | `public/assets/video/` | 是 |
| 字体、谱面、关卡数据 | `public/assets/fonts/`、`public/assets/data/` | 是 |
| 策划参考图、原图、附件 | `docs/图片和附件/` | 否 |

运行时代码只可从 `public/assets/` 加载资源。Phaser 路径必须通过 `import.meta.env.BASE_URL` 拼接，不能写死 `/assets/`，以兼容 GitHub Pages 的仓库子路径。

## 角色序列帧

当前玩家与角色特效的正式制作依据为飞书知识库 [Si想家-角色特效规范](https://lilithgames.feishu.cn/wiki/N1fTwofxXiMNs2k8H8VcTX9jnnd?from=from_copylink)（Docx revision `750`，复核于 `2026-08-15`）。其中明确要求：开发分辨率 `1920 x 1080`、像素图使用 Nearest Neighbor、角色与特效帧为 `256 x 256px`、棍状武器为 `128 x 128px`，玩家棍状武器层级为“武器 > 角色 > 特效”。本地实现为维持现有屏幕占比，允许角色/特效低于原生 `1x` 显示；不得因此改变源文件画布规格。

角色素材默认只绘制**朝右**版本；向左运动由 Phaser 的 `setFlipX(true)` 完成。

```text
public/assets/images/characters/<角色>/animation/<动作>/<角色>_<动作>_<两位序号>.png
```

示例：

```text
public/assets/images/characters/player/animation/run/player_run_01.png
public/assets/images/characters/player/animation/dash/player_dash_01.png
public/assets/images/characters/npc/npc_guard01/animation/idle/npc_guard01_idle_01.png
```

- 只把实际播放的帧提交进运行时目录；站定测试帧、重复帧和废弃导出帧应在导入时清掉。
- **先校准，再接入引擎。** 导入前必须逐帧检查透明内容边界、脚底基线和像素高度；不得根据完整画布大小直接设置统一显示尺寸。
- 以一个动作作为视觉基准，同一动作的所有帧必须检查透明内容边界和脚底基线；宽度按原比例变化，不得为统一宽高而拉伸。
- 不同动作可以使用不同内容高度。旧粉丝可变画布的跑步 / 翻滚 / 近战校准值只属于历史素材，不得继续套用到正式 `npc_fan01` 的 `256 x 256px` 方形帧。
- 正式红发玩家素材统一使用 `256 x 256px` 透明画布：Idle 8 帧、Run 8 帧、Dash 12 帧、Attack Light / Hard 各 5 帧、Death1 / Death2 各 8 帧。Attack Light / Hard PNG 是纯特效层，只能用独立 Sprite 叠加，不得替换本体纹理；特效必须与角色画布同中心、同翻转并在播放期间跟随角色，深度低于武器和角色。当前 Light 三张代表帧的非透明像素均只有 `Alpha=255`，并非引擎丢失渐变，运行时统一乘 `0.45` Alpha；Hard 代表帧含 `246` 档 Alpha，保留素材渐变并使用角色基准的 `1.18x`。预览 GIF 仅是角色与特效的合成预览。轻攻击输入只播放 Attack Light，重攻击输入只播放 Attack Hard，错误输入也按实际按键选择表现。
- 1080p 内部画布中，玩家本体与 Light 特效基准按约 `0.7067x` 显示，可见内容高约 `76.3px`，固定受击体约 `29.7 x 76.3px`；Hard 特效在此基础上乘 `1.18`。缩放到旧 720p 窗口时玩家本体仍约为 `50.9px / 19.8 x 50.9px`，用于维持本轮修改前的屏幕视觉大小。不得擅自把玩家本体改为原生 `1x`。
- 玩家正式手持贴图固定使用 `images/weapons/light_stick/player/light_stick_player.png` 与 `images/weapons/baton/player/baton_player01.png`，源图必须为 `128 x 128px`。当前显示比例约 `0.5653x`；旋转原点必须使用透明内容的握把末端，荧光棒为 `(101/128, 98/128)`、警棍为 `(123/128, 121/128)`。原点固定在角色腰部中线、内部下移 `22.5px`（FIT 到旧 720p 窗口等效 `15px`）。非中心 Origin 禁止用 Phaser `flipX` 翻 UV；另一朝向必须保持 `flipX=false`，改用负 `scaleX` 围绕 Origin 做几何镜像，并同步反转挥击角。绘制深度必须略高于所属玩家，玩家层级由前到后为“武器 > 角色 > 特效”；不得再用程序矩形棒替代。
- 当前正式资源目录没有截图中展示的 Pick 序列帧。不得用 Attack、Dash 或 Idle 冒充 Pick；补齐素材后再同步更新 preload、状态机、资源验收和文档。
- 已核对现有 54 张玩家动画 / 特效 PNG 均为 `256 x 256px`，两张玩家正式武器及其 8 个候选 PNG 均为 `128 x 128px`。
- 正式橙色粉丝运行时使用 `images/characters/npc/npc_fan01/animation/run/` 的 8 张 `256 x 256px` 帧；第 4 拍攻击使用 `attack_hard/` 的 `02–07` 共 6 张透明特效帧；专属武器为 `images/weapons/light_stick/npc_fan01/light_stick_fan01.png`（`128 x 128px`）。由于画布规格与玩家一致，粉丝本体必须复用玩家本体约 `0.7067x` 的运行时倍率，粉丝武器必须复用玩家武器约 `0.5653x` 的倍率，不得套用 `1.2x` 程序化世界物件倍率。Hard 特效六帧必须由场景时钟在 `500ms` 内手动切换贴图，不得注册或调用 Phaser Animation `.play()`；当前引擎版本在该独立特效首次播放时会锁住主线程。运行时层级必须为“角色 > 武器 > 特效”，特效使用 ADD 混合。仓库中的旧 `images/characters/fan/` 素材不再由 `FanEnemy` 加载，仅保留历史来源，不得与正式帧混用。
- 每个动作完成裁切和缩放后，至少目视检查一张基准帧和一张幅度最大的帧，确认脚底不跳、攻击不显小、透明边缘不影响比例。
- 新动作必须同时更新 `preload`、运行时帧推进路径、敌人/角色状态切换和更新记录；循环角色本体通常注册 Phaser Animation，已记录存在引擎锁死风险的独立特效必须使用项目指定的安全帧调度方式。
- 保持透明背景，单帧建议不超过 `1MB`。

## 通用命名与验收

- 新文件使用小写英文、数字与连字符；不得使用“final”“new”“v2”或模糊的临时后缀。
- 角色/敌人放 `images/characters/`，武器放 `images/weapons/`，视觉特效放 `images/effects/`，背景放 `images/backgrounds/`，UI 放 `images/ui/`。
- 音效放 `audio/sfx/`，BGM 放 `audio/music/`。音效键与文件名的映射须在加载代码中保持可追溯。
- 开场和过场视频放 `video/`，使用浏览器可播放格式；带声音的视频必须处理自动播放锁定。
- 导入后执行 `npm run build`，本地预览确认资源返回 200、控制台无资源 404、实际播放帧与逻辑状态一致。
- `dist/`、浏览器测试截图、下载残留和无引用的临时导出图不得提交。
