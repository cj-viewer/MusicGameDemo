## 2. 2026-08-09 拉取基线

开发基线来自仓库 `cj-viewer/MusicGameDemo` 的 `dev-1.0` 分支。刚拉取时可以确认的原型状态如下：

### 2.1 工程状态

- 技术栈为 Phaser 4、TypeScript、Vite，逻辑分辨率为 `1280 x 720`。
- 已有 `Conductor` 统一节拍时钟，BPM 为 `120`，拍号按每小节 4 拍处理。
- 已有轻拍/重拍输入、ComboMeter、Fever Time、三波敌人、武器掉落和 WebAudio 合成音效。
- 已有简化策划案和完整版策划案的 Markdown 转写文件。
- 角色、敌人和场地以程序图形及临时占位表现为主，尚未形成当前的保安、外星玩家角色素材组合。
- README 中的操作和部分代码注释与实际策划需求存在偏差，中文文本还存在历史编码显示异常。

### 2.2 玩法基线

- 玩家使用 `WASD` 直接移动，移动没有当前版本的惯性。
- 闪避键为 `Space`，闪避方向和后续要求不完全一致。
- 武器攻击由扇形近战、蓄力和突进等不同 `AttackSpec` 组成，并非统一弹幕。
- 部分攻击自带角色位移。
- 错误输入会清空 ComboMeter，并锁定当前小节后续攻击。
- 敌人攻击频率和节拍内行为各不相同，并非统一为每小节一次三发攻击。
- 节拍提示音虽然由 `Conductor` 调度，但轻重音与每个武器小节内的轻重分布未完全对齐。
- 命中反馈、边缘节拍律动、节拍同步的事件音效优先级均未形成当前规则。

### 3.9 2026-08-10：荧光棒弹幕与节拍喊声回归修复

- 问题：拍点前输入时，荧光棒弹丸使用 `floor(beatFloat) + 1` 计算销毁拍，可能把即将到来的判定拍误当成“下一拍”，导致弹丸只显示几十毫秒，看起来像没有发射。
- 修复：销毁拍改为 `nearestBeat(now).n + 1`，即以本次输入判定到的拍为基准再延后一拍。拍前输入跨过判定拍后仍会继续存在，直到真正的下一拍。
- 问题：自定义 MP3 的旧实现直接读取缓存 `AudioBuffer`；读取失败时会静默回退正弦合成音，因此用户仍可能听到原节拍音，且无法从界面判断回退发生。
- 修复：改为通过 Phaser 已加载的 `WebAudioSound` 实例播放 `beat-light` / `beat-heavy`，使用 `delay` 保持拍点调度，并彻底删除旧正弦节拍回退。
- 音频键缺失时现在会明确输出 error 并保持静音，不再播放错误的旧节拍音。
- 为保证喊声在默认状态仍清楚可辨，基础响度调整为 `0.16`；正确攻击四拍响度调整为 `0.28 / 0.40 / 0.52 / 0.64`。
- 回归结果：浏览器诊断确认正确攻击生成 5 发，拍前输入后的存续时间约 `479ms`；两个自定义音频键均成功加载，页面无音频加载错误。

### 3.12 2026-08-10：武器底端挥动与 Fever 能量倍率

- 武器示意不再转向瞄准角并进行大范围扫动，而是以每根武器的柄底为固定旋转轴，从竖直待机角度向射击方向所在的左侧或右侧偏转。
- 双持应援棒的示意挥动角度为 `30°`，两根棒分别围绕各自底端同步偏转。
- 保安棍的示意挥动角度为 `50°`，围绕棍子底端偏转。
- 本轮只修改角色身上的武器动画；应援棒弹幕 30 度总扇区、警棍轻重攻击 90 / 120 度扫击范围均保持不变。
- Fever 能量获取倍率统一改为 `3x`：正确输入和换武器演示由基础 `+2` 结算为 `+6`，踩拍闪避由基础 `+1` 结算为 `+3`；错误输入仍不获取能量。
- `F` 调试键仍会直接将能量充满到 `100`，不改变调试用途。
- 验证结果：TypeScript 类型检查和 Vite 生产构建通过；浏览器实机截图确认应援棒可围绕固定底端分别向左、向右小幅偏转，页面无 error/warn；独立运行测试确认倍率为 `3`、基础 `2 → 6`、基础 `1 → 3`。

### 3.13 2026-08-10：错误输入单中弹与 Fever 半速维持

- 错误输入时，应援棒从 3 发改为只生成瞄准方向正中的 1 发；保安棍继续只保留三层弧段中的中层 1 段。
- Fever 期间仍允许正常进行轻重输入判定。正确输入以普通阶段一半的效率回充：普通正确输入获取 `6` 点，Fever 内正确输入按 `3` 点计算。
- Fever 满能量对应 `16拍`，因此每次 Fever 内正确输入延长 `3 / 100 × 16 = 0.48拍`。
- 回充后的剩余时长最多为完整 `16拍`，不能预存超过满能量上限；错误输入不回充。
- Fever 结束检测由整数拍事件改为逐帧读取浮点拍位置，确保 `0.48拍` 回充不会被错误地向上取整为 1 拍。
- 验证结果：TypeScript 类型检查和 Vite 生产构建通过；独立运行测试确认正确输入延长 `0.48拍`、错误输入延长 `0拍`，并能在小数拍截止点精确结束；浏览器以首拍错误重击确认应援棒只生成正中 1 发，页面无 error/warn。

### 3.14 2026-08-10：手柄输入与震动适配

- Phaser 游戏配置启用 Gamepad 插件，使用浏览器标准手柄布局：左摇杆移动、右摇杆瞄准、`LB` 闪避、`RB` 轻拍、`RT` 重拍。
- 左右摇杆统一使用 `0.2` 径向死区；左摇杆保留模拟量幅度控制移速，不强制归一化为满速。
- 右摇杆有输入时接管瞄准并继续使用 90 度辅助瞄准；松开后保持最后方向，鼠标再次移动时切回鼠标瞄准。
- `LB / RB / RT` 使用按下沿触发，持续按住不会逐帧重复提交输入；在标题界面按任一已映射肩键可开始游戏。
- `RB / RT` 进入与鼠标相同的轻重拍判定。只有正确输入触发震动：轻拍 `60ms` 小震动，重拍 `130ms` 大震动；错误输入不震动。

- Fever 期间只有正确输入会以半速回充，每次按 `3` 点延长 `0.48拍`，最多回充到剩余 `16拍`。

### 4.6 节拍表现和音效

- 轻重提示音读取当前武器的四拍输入序列。
- 教学关保留顶部四拍连段，但不再显示底部汇聚节奏条；改与正式游戏一样读取三拍场地判定框。按键种类正确、距原始拍点 `≤180ms` 的输入会成为校准候选，其中 `≤120ms` 的稳定样本自动以中位数 + MAD 离群剔除估算设备延迟，补偿限制为 `±120ms`，只影响后续输入判定。
- 左、右各 38 根、下侧 64 根深紫粉竖直律动条按受控随机的交错轨道铺开：下侧横向 `±5px`、纵向 `±4px`，左右横向 `±4px`、纵向 `±2.5px`，既有自然错落也避免完全重叠；单根宽 `22–26px`，左右高度 `36–40px`、下侧高度 `42–50px`，透明度始终为 `1`。轻拍明度 / 饱和度变化约 `+3% / -3%`，重拍约 `+5% / -5%`；三侧轻 / 重跳高统一约 `1.3x / 1.85x`。律动条无碰撞盒，允许侵入战斗区。
- 律动条和角色统一按脚底 Y 做 TopDown 排序；越靠下越遮挡上方对象。角色所属武器、瞄准反馈和血条与角色保持相邻深度。
- 事件音效在整数拍结算，单拍优先级为：玩家受伤 > Fever > 敌人受伤 > 武器拾取。
- 攻击、错误输入、Combo 等即时操作音仍按各自现有逻辑触发。
- 轻拍使用单人 `-13dB` 版 `beat-light.mp3`，重拍使用多人 `+0dB` 版 `beat-heavy.mp3`；音频由 Phaser `WebAudioSound` 提前调度，分别在理论拍点前 `70ms / 74ms` 开始播放。
- 轻、重叫喊统一使用固定音量 `0.28`，不因输入是否正确或拍位改变；重叫喊在素材时间 `330–360ms` 淡出。
- BGM 使用 `audio/music/bgm3.mp3`，滑杆默认对外显示 `100%`，内部基础音量为 `0.1`；其文件内首拍偏移 `0.026s`，与 Conductor 第 0 拍对齐。每 `616` 拍重新校相，重开时必须先停止旧 `bgm` 实例。
- 主音量默认 `150%`、范围 `0–300%`；BGM 与音效通道默认 `100%`、范围各 `0–200%`。BGM 通道缩放 BGM 基础音量，音效通道统一缩放轻重节拍采样与 `Sfx` 程序合成反馈，二者最终仍经过 Phaser 主音量节点。设置打开时 Conductor、音频、物理、动画、Tween、Scene Clock 和玩法输入均暂停；恢复后拍点与 BGM 继续同相。
- 右下 `240 x 153px` FPV 观察窗是独立 Scene 的只读投影，锚定逻辑屏幕右下且右、下边缘均为 `20px`，只显示玩家朝向、敌人、敌我弹幕和拍相。它不拥有输入且不改变主场景相机、HUD、移动、攻击、判定或 AI；用户可在 Esc 设置中关闭。观察方向读取玩家当前自动锁定角。
- 圆形能量表标题常驻显示 `ComboMeter`；Fever 期间只改变标题颜色和表盘状态，中央爆发提示仍显示 `FEVER TIME!`。
- 教学和正式游戏均隐藏 HUD 底部节奏条，并同时预览未来 `3` 拍的三个场地内框。每框从 `0.7x` 且全透明状态在 `3` 拍内按 `easeInExpo` 扩散并淡入到 `1x`。轻拍为粉紫 `#e879f9`，重拍为橙色 `#f97316`；内框到达大场地框即为对应拍点并立即隐藏。正确输入（含自动演示）会额外以同色粗框轻微外扩并淡出，提供独立于到拍亮框的命中反馈。

### 4.7 武器示意

- 武器示意跟随自动锁定方向：握把固定在瞄准线起点（角色中心向锁定方向约 `16.8px`），棒身实时指向锁定方向，与白色瞄准短线重合。
- 荧光棒为单根红色短棒（尺寸 `24 x 6px`）；警棍为单根紫色棒（尺寸 `40.8 x 7.2px`）。
- 握把是旋转轴；挥击从偏转角收敛回瞄准线（朝指向劈下的观感），方向在角色右侧时向右偏、在左侧时向左偏。
- 应援棒示意挥动 `30°`，保安棍示意挥动 `50°`；这些数值不影响弹幕攻击覆盖范围。
- 挥动固定在 `200ms` 内结束，不再卡下一整数拍；新攻击会打断并重新开始。

### 4.8 手柄反馈

| 事件 | 震动参数 |
|---|---|
| 正确轻拍 | `60ms`，弱马达 `0.25`、强马达 `0.08` |
| 正确重拍 | `130ms`，弱马达 `0.65`、强马达 `0.90` |
| 成功闪避 | `90ms`，弱马达 `0.45`、强马达 `0.35` |
| 错误输入 / 闪避失败 | 不震动 |

震动通过浏览器 `GamepadHapticActuator.playEffect('dual-rumble')` 调用；无执行器或调用被浏览器拒绝时不影响操作。

## 6. 跨系统实现约束

后续修改必须同时检查以下关系：

1. 修改武器 `pattern` 时，必须同时验证节拍提示音、HUD 节奏块、自动演示和轻重攻击方向。
2. 修改弹丸寿命时，优先使用 `Conductor` 的拍位置，不要用独立墙钟模拟整数拍规则；警棍固定 `150ms` 是明确例外。
3. 修改攻击数量时，必须分别检查正确输入、错误输入、换武器自动演示和 Fever 附加攻击。
4. 修改玩家自动瞄准时，必须以最后一次有效移动方向作为前方扇区中心；扇区总角度 `45°`，内部目标的有效距离为实际距离一半，不得用上一帧锁定角递归选敌。
5. 修改警棍轨迹时，画面弧段与透明物理命中框必须同步销毁，避免残留 Graphics 或幽灵碰撞体。
6. 修改移动手感时，闪避必须仍以当前按键方向为准，而不是速度惯性方向或鼠标方向。
7. 新增节拍音效时，必须明确是否进入优先级队列；进入队列的事件必须说明同拍冲突顺序。
8. 手持武器示意挥击固定为 `200ms`，不得再绑定下一整数拍；新攻击必须停止旧 Tween 并从头播放。
9. 修改节拍采样或响度时，必须同时验证提前输入和延后输入；已有采样应优先调整同一个声音实例，避免无意义叠音。
10. 修改指数波次数量或混编比例时，必须检查出生点分布、碰撞性能，以及警棍和荧光棒的掉落去重。
11. 修改任何当前玩法、参数、素材或输入后，必须同步更新 README、简化原型文档和本记录；完整版策划案的当前快照也必须保持一致。
12. 修改资源路径或 Vite 基础路径时，必须同时验证本地根路径和 GitHub Pages `/MusicGameDemo/` 子路径。
13. 新增或迁移素材时，必须按 README「资源与资产上传规则」放入对应类型目录并规范命名，同时更新加载代码、README 和本记录；策划参考图只能放在 `docs/图片和附件/`，不得直接进 `public/assets`。
14. 部署工作流只由 `main` 推送自动触发；修改触发分支时必须同时核对 README、本记录和 GitHub Pages 发布源设置。
15. 粉丝素材默认朝右；不得添加重复左向帧。修改其移动状态时，慢行 / 突进 / 攻击必须分别保持跑步 / 翻滚 / 近战的视觉映射，并同步核对显示尺寸、`setFlipX` 和碰撞半径。
16. 新增或替换任何序列帧前，必须逐帧测量透明内容边界。只要求同一动作内部统一高度；不同动作应以跑步等基准动作目视比较后独立定高，宽度必须保持等比，禁止为了统一宽高而拉伸。
17. 粉丝动画状态优先级必须为：受击翻滚 > 攻击近战 > 拍前翻滚 > 拍间跑步；受击或攻击不能被同一帧的移动状态覆盖。玩家使用独立的女高中生序列帧（`player-idle/run/down`），不得加载、引用或播放粉丝动画帧，也不得因粉丝动画改动被替换。
18. 修改节拍叫喊素材时，必须重新测量有效起声与尾音，分别校准提前量和淡出点；正确输入不得改变叫喊音量，避免拍后中途增益跳变。
19. 修改 BGM、BPM 或循环素材时，必须保证循环拍数为四拍小节的整数倍，并在每轮开始时按 Conductor 重新校相。
20. 新增任何可听音效时，必须接入 Phaser 音频总线并受统一主音量控制，不得直接绕过主音量连接到 `AudioContext.destination`。
21. 修改战斗区或边缘律动带时，必须同步验证物理边界、Fever 边框、敌人出生点、弹丸清理和 HUD；边缘律动条保持竖直且不得重新占用顶部区域。
22. 场内角色或物件尺寸调整必须经过统一 `WORLD_OBJECT_SCALE`，同步视觉尺寸、碰撞体、手持物、掉落和弹幕；不得缩放 HUD、场地或节奏条。
23. 边缘律动条必须始终保持完全不透明；亮拍反馈只允许在同一基础色上提高明度、降低饱和度，不得重新引入 alpha 闪烁或半透明叠色。
24. 边缘律动条宽度保持近似，高度只允许轻微错落；如需增加人群丰满度，优先调整数量和重叠密度，不得重新扩大单条体型随机范围。
25. 边缘律动条整体体型应接近当前缩放后角色，数量以不形成连续拥堵为准；降低高亮饱和度时必须保留可辨认的紫粉色，不得再次大面积灰白化。
26. 律动条不得添加物理 Body 或碰撞盒，允许其视觉侵入战斗区；律动条、角色及所属视觉必须按脚底 Y 使用同一 TopDown 深度规则，禁止用固定角色类型 depth 打破前后遮挡。
27. 律动条轻重拍的明度和饱和度单项变化均不得超过 `5%`，透明度保持 `1`。
28. HP 血条的节拍律动只允许修改纵向厚度和不超过 `5%` 的色差；横向 `scaleX` 必须只由当前生命比例控制，HP 数字不得参与缩放。
29. 右下 FPV 观察窗必须只读主场景数据，禁止注册或截获键鼠/手柄输入，禁止写入移动、攻击、判定、AI、HUD、相机或物理状态；它只能作为可关闭的视觉投影。视角读取玩家当前自动锁定角。
30. 设置面板只能由 `Esc` 开关。面板可见期间，Conductor、音频、物理、动画、Tween、Scene Clock 和玩法输入必须全部暂停；恢复后需保证 BGM 与节拍时钟仍同相。

## 8. 后续更新模板

每次 Vibe Coding 修改后，在“当日调整记录”末尾追加：

```md
### YYYY-MM-DD / 调整主题

- 需求：修改了什么规则。
- 实现：修改了哪些文件和核心参数。
- 兼容：对节拍、输入、弹幕、音效、HUD、素材的影响。
- 验证：执行的构建命令和实际试玩结果。
- 遗留：仍未实现或需要策划确认的内容。
```

不要只记录“优化手感”“调整表现”等模糊描述；必须写明数值、方向、寿命、触发时机和冲突规则。
