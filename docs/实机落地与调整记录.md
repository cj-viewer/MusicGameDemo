## 2. 2026-08-09 拉取基线

开发基线来自仓库 `cj-viewer/MusicGameDemo` 的 `dev-1.0` 分支。刚拉取时可以确认的原型状态如下：

### 2.1 工程状态

- 技术栈为 Phaser 4、TypeScript、Vite，逻辑分辨率为 `1280 x 720`。
- 已有 `Conductor` 统一节拍时钟，BPM 为 `120`，拍号按每小节 4 拍处理。
- 已有轻拍/重拍输入、ComboMeter、Fever Time、三波敌人、武器掉落和 WebAudio 合成音效。
- 已有简化策划案和完整版策划案的 Markdown 转写文件。
- 角色、敌人和场地以程序图形及临时占位表现为主，尚未形成当前的保安、外星玩家角色素材组合。
- README 中的操作和部分代码注释与实际策划需求存在偏差，中文文本还存在历史编码显示异常。

### 2.2 玩法基线

- 玩家使用 `WASD` 直接移动，移动没有当前版本的惯性。
- 闪避键为 `Space`，闪避方向和后续要求不完全一致。
- 武器攻击由扇形近战、蓄力和突进等不同 `AttackSpec` 组成，并非统一弹幕。
- 部分攻击自带角色位移。
- 错误输入会清空 ComboMeter，并锁定当前小节后续攻击。
- 敌人攻击频率和节拍内行为各不相同，并非统一为每小节一次三发攻击。
- 节拍提示音虽然由 `Conductor` 调度，但轻重音与每个武器小节内的轻重分布未完全对齐。
- 命中反馈、边缘节拍律动、节拍同步的事件音效优先级均未形成当前规则。

### 3.9 2026-08-10：荧光棒弹幕与节拍喊声回归修复

- 问题：拍点前输入时，荧光棒弹丸使用 `floor(beatFloat) + 1` 计算销毁拍，可能把即将到来的判定拍误当成“下一拍”，导致弹丸只显示几十毫秒，看起来像没有发射。
- 修复：销毁拍改为 `nearestBeat(now).n + 1`，即以本次输入判定到的拍为基准再延后一拍。拍前输入跨过判定拍后仍会继续存在，直到真正的下一拍。
- 问题：自定义 MP3 的旧实现直接读取缓存 `AudioBuffer`；读取失败时会静默回退正弦合成音，因此用户仍可能听到原节拍音，且无法从界面判断回退发生。
- 修复：改为通过 Phaser 已加载的 `WebAudioSound` 实例播放 `beat-light` / `beat-heavy`，使用 `delay` 保持拍点调度，并彻底删除旧正弦节拍回退。
- 音频键缺失时现在会明确输出 error 并保持静音，不再播放错误的旧节拍音。
- 为保证喊声在默认状态仍清楚可辨，基础响度调整为 `0.16`；正确攻击四拍响度调整为 `0.28 / 0.40 / 0.52 / 0.64`。
- 回归结果：浏览器诊断确认正确攻击生成 5 发，拍前输入后的存续时间约 `479ms`；两个自定义音频键均成功加载，页面无音频加载错误。

### 3.12 2026-08-10：武器底端挥动与 Fever 能量倍率

- 武器示意不再转向瞄准角并进行大范围扫动，而是以每根武器的柄底为固定旋转轴，从竖直待机角度向射击方向所在的左侧或右侧偏转。
- 双持应援棒的示意挥动角度为 `30°`，两根棒分别围绕各自底端同步偏转。
- 保安棍的示意挥动角度为 `50°`，围绕棍子底端偏转。
- 本轮只修改角色身上的武器动画；应援棒弹幕 30 度总扇区、警棍轻重攻击 90 / 120 度扫击范围均保持不变。
- Fever 能量获取倍率统一改为 `3x`：正确输入和换武器演示由基础 `+2` 结算为 `+6`，踩拍闪避由基础 `+1` 结算为 `+3`；错误输入仍不获取能量。
- `F` 调试键仍会直接将能量充满到 `100`，不改变调试用途。
- 验证结果：TypeScript 类型检查和 Vite 生产构建通过；浏览器实机截图确认应援棒可围绕固定底端分别向左、向右小幅偏转，页面无 error/warn；独立运行测试确认倍率为 `3`、基础 `2 → 6`、基础 `1 → 3`。

### 3.13 2026-08-10：错误输入单中弹与 Fever 半速维持

- 错误输入时，应援棒从 3 发改为只生成瞄准方向正中的 1 发；保安棍继续只保留三层弧段中的中层 1 段。
- Fever 期间仍允许正常进行轻重输入判定。正确输入以普通阶段一半的效率回充：普通正确输入获取 `6` 点，Fever 内正确输入按 `3` 点计算。
- Fever 满能量对应 `16拍`，因此每次 Fever 内正确输入延长 `3 / 100 × 16 = 0.48拍`。
- 回充后的剩余时长最多为完整 `16拍`，不能预存超过满能量上限；错误输入不回充。
- Fever 结束检测由整数拍事件改为逐帧读取浮点拍位置，确保 `0.48拍` 回充不会被错误地向上取整为 1 拍。
- 验证结果：TypeScript 类型检查和 Vite 生产构建通过；独立运行测试确认正确输入延长 `0.48拍`、错误输入延长 `0拍`，并能在小数拍截止点精确结束；浏览器以首拍错误重击确认应援棒只生成正中 1 发，页面无 error/warn。

### 3.14 2026-08-10：手柄输入与震动适配

- Phaser 游戏配置启用 Gamepad 插件，使用浏览器标准手柄布局：左摇杆移动、右摇杆瞄准、`LB` 闪避、`RB` 轻拍、`RT` 重拍。
- 左右摇杆统一使用 `0.2` 径向死区；左摇杆保留模拟量幅度控制移速，不强制归一化为满速。
- 右摇杆有输入时接管瞄准并继续使用 90 度辅助瞄准；松开后保持最后方向，鼠标再次移动时切回鼠标瞄准。
- `LB / RB / RT` 使用按下沿触发，持续按住不会逐帧重复提交输入；在标题界面按任一已映射肩键可开始游戏。
- `RB / RT` 进入与鼠标相同的轻重拍判定。只有正确输入触发震动：轻拍 `60ms` 小震动，重拍 `130ms` 大震动；错误输入不震动。

- 正确攻击每拍获取 `6` 点；闪避不再获取能量，正确 / 错误分别消耗 `10 / 20` 点。换武器不再自动演示或获取能量。

### 4.6 节拍表现和音效

- 轻重提示音读取当前武器的四拍输入序列。

- 正式关粉紫音乐广场的 35 个透明物件读取同一整数拍事件，以各自底边中点为 Origin 同步回弹。轻拍目标比例为基础 `scaleX / scaleY` 的 `1.003 / 1.01`、单程 `80ms`；重拍为 `1.006 / 1.022`、单程 `110ms`，统一使用 `Quad.easeOut + yoyo` 回到基础比例。新拍开始前会先终止旧补间并恢复基准，避免缩放累积。`pink-stage-runtime-base.png` 与 `pink-stage-clean-background.png` 从不加入补间目标；教学池塘场景也不会触发这组物件动画。
- 玩家、保安和粉丝继续按脚底 Y 做 TopDown 排序；越靠下越遮挡上方对象。角色所属武器、瞄准反馈和血条与角色保持相邻深度。
- 事件音效在整数拍结算，单拍优先级为：玩家受伤 > Fever > 敌人受伤 > 武器拾取。
- 攻击、错误输入、Combo 等即时操作音仍按各自现有逻辑触发。
- 每次已结算的玩家攻击在实际攻击锚点附近弹出小型 `PERFECT / GOOD / POOR`，并以更小副标显示 `EARLY / LATE + 毫秒数`。字体为粗斜体、深色描边和轻微纵向渐变；Perfect 为金色，Good 为蓝色，Poor 为灰色。入场轻微弹起，停留后继续上浮消隐，动效结束销毁；浮字 depth 固定为生成瞬间玩家本体之后，设置面板仍高于浮字。
- 轻拍使用单人 `-13dB` 版 `beat-light.mp3`，重拍使用多人 `+0dB` 版 `beat-heavy.mp3`；音频由 Phaser `WebAudioSound` 提前调度，分别在理论拍点前 `70ms / 74ms` 开始播放。
- 轻拍叫喊使用固定音量 `0.42`，重拍使用 `0.28`，均不因输入是否正确或拍位改变；重叫喊在素材时间 `330–360ms` 淡出。
- BGM 使用 `audio/music/` 下的四首可选音轨，滑杆默认显示 `100%`，内部基础音量为 `0.084375`，延续旧版默认有效响度。Conductor 固定为 `132 BPM`；每首曲目以 `132 / 源 BPM` 的倍率播放，源文件首拍偏移会除以该倍率换算成墙钟时间，迟到启动时的 `seek` 则乘回该倍率。各曲目在自身的循环拍数边界重新校相，重开时必须先停止旧 `bgm` 实例。
- 主音量、BGM、节拍喊声、攻击与错误、受伤与敌亡、Combo、Fever、拾取八路音量默认均为 `100%`，范围均为 `0–100%`。BGM、Conductor 采样与 `Sfx` 分类分别应用对应通道，最终仍经过 Phaser 主音量节点。Esc 音量面板不使用全屏暗罩或深色隐私底；打开后抓取面板后方 `900 x 975px` 暂停帧并外扩 `24px` 采样，通过 Canvas `blur(14px) saturate(82%) brightness(106%)` 得到背景模糊，再叠加 `#f2f0e8 / 0.18` 半透明雾面和白色 Alpha `0.10 → 0.035` 轻渐变。面板文字优先使用“Microsoft YaHei UI / Microsoft YaHei”并以 Text `resolution=2` 渲染；标题、分类、八路标签与关闭提示均使用锁定的准确文案。打开时 Conductor、音频、物理、动画、Tween、Scene Clock 和玩法输入均暂停；恢复后拍点与 BGM 继续同相。
- 右下 FPV 观察窗是独立 Scene 的只读投影，1080p 内部尺寸为 `360 x 229.5px`、右下边距 `30px`，FIT 后仍保持旧版约 `240 x 153px / 20px` 的屏幕占比。它只显示玩家朝向、敌人、敌我弹幕和拍相，不拥有输入且不改变主场景相机、HUD、移动、攻击、判定或 AI；用户可在 P 调参面板中关闭。
- 圆形能量表标题常驻显示 `ComboMeter`；Fever 期间只改变标题颜色和表盘状态，中央爆发提示仍显示 `FEVER TIME!`。
- 教学连段 UI 继续使用 `tutorial-pattern-panel.png` 的 `578 x 278` RGBA 原图，运行时放入 `x=114.070983、y=86.035871、w=354.689738、h=170.594718` 的矩形。原图中的标题、框线和四拍格完整显示；每拍脉冲与正确命中分别裁剪同图对应格并以 ADD 在 `150 / 220ms` 内淡出。Photoshop 的 `247 x 163` 进度面板放在 `(167,249)`，`1556 x 50` 底部状态条放在 `(188,890)`；两者均为静态合成图。四张 `320 x 64` 操作卡分别放在 `(130,450) / (128,549) / (128,648) / (128,747)`，不移动、不缩放，并严格按鼠标左键轻攻、鼠标右键重攻、Esc 设置、L / R Shift 冲刺逐项显示。同一时刻最多显示当前一张：首项延迟 `160ms` 后以 `280ms Sine.easeOut` 淡入，真实操作完成后以 `220ms Sine.easeInOut` 淡出，间隔 `100ms` 后淡入下一张；第四项完成后不再循环。卡片只有在有效的淡入 Tween 真正开始时才加入当前页面会话的已展示集合；重练或 `R` 重开从第一张未展示卡继续，四张均已展示时不再创建侧边卡，完整刷新页面才重置。过渡期重复输入和提前输入不跳步，非当前输入仍执行原玩法；Esc 打开设置时同步记为完成，关闭设置恢复场景后继续视觉过渡。进入 `tutorialConfirm`、Space 跳过、进入第二关或 Scene 关闭时停止并清理当前任务和 Tween。旧程序化 WASD 两栏卡和 `SPACE 跳过教学` 可见文字不再创建，但对应输入逻辑不变。正式关使用 `320 x 64px` 的透明紧凑布局，不再创建 `0x0f172a / 0.68` 黑色矩形或 `0x334155` 描边；只保留当前武器 pattern 的四个程序图案并继续逐拍高亮，切换武器会按新 pattern 重建图案。
- 教学和正式游戏均隐藏 HUD 底部节奏条，也不再创建未来 `3` 拍的三个整场缩放框；`INPUT_EARLY_WINDOW=0.2s` 的攻击判定、轻重 pattern、Conductor 与音效调度不因视觉删除而改变。正确输入仍可短暂显示命中反馈，亮度随连续踩拍积累并在拍间衰减；连续 4 次正确输入仍在四边喷出 84 个双向 ADD 光屑，并叠加双层瞬时边框冲击波、宽光带、四角星爆与轻微镜头震动。两关拍间都不绘制常驻或循环扩散的战斗区外框，所有保留短效结束后也不会恢复它们。

- 教学容器内的固定绘制顺序为“进度面板 → `(188,890)` 的 `1556 x 50` 静态底栏 → `(89,877)` 的 `1704 x 112` `tutorial-bottom-rocks.png` 前景 → 四条操作卡”。石子因此遮住底栏对应区域，但不遮住操作卡；它不带碰撞或节拍动画，并在进入第二关、跳过或 Scene 关闭时随教学容器一同销毁。

### 4.7 武器示意

- 荧光棒和警棍分别使用正式玩家贴图 `light_stick_player.png / baton_player01.png`，不再使用程序矩形短棒。
- 武器源图为 `128 x 128px`，当前约 `0.5653x`。荧光棒 / 警棍旋转原点分别为握把末端 `(101/128, 98/128)`、`(123/128, 121/128)`；世界旋转轴固定在角色腰部中线、内部下移 `22.5px`。武器始终 `flipX=false`，另一朝向使用负 `scaleX` 围绕 Origin 做几何镜像，挥击角同步反号。
- 武器不实时旋转到瞄准线；轻 / 重攻击分别执行较小 / 较大的非线性挥击，默认在 `200ms` 内回到握持角。P 调参面板可分别把荧光棒 / 警棍攻击动作速度调为 `50–200%`，动作、特效和动作锁按倒数缩放，但判定窗口不变。
- 自动索敌不显示白色攻击方向短线；该指示的删除不改变实际索敌角或弹幕方向。
- 警棍扫击和 Fever 波仍使用角色中心向当前朝向侧偏移约 `7.68px` 的既有攻击锚点；荧光棒直射改用下一条记录的武器发光端坐标。轻 / 重素材特效与角色同中心、同翻转并跟随播放，保持现有尺寸；Light / Hard 分别使用亮黄 `#fff36b` / 紫粉 `#f28cff` 填色、Alpha `0.72 / 0.92`，单一 Sprite 使用 ADD + Glow + Bloom。层级由前到后为“武器 > 角色 > 特效”。
- 荧光棒直射读取源图发光帽外沿中心 `(29.5, 27.5)`，按武器当前的非中心 Origin、正负 `scaleX` 与挥击旋转换算后，再沿每条弹道方向前移 `28.8px` 放置亮芯尾端；透明物理宿主位于该前置点沿发射方向再前移原判定长度一半的位置，因此三点判定段与亮芯从同一点、沿同一轴线开始，可见空隙内没有隐藏判定。
- 荧光棒正确踩拍将直射芯切换为纯白 `0.96` Alpha；普通芯为 `66%` 近白混色、`0.94` Alpha，两者共用红色连续衰减外晕。旧双层冲击环和白色方向楔形不再生成；保留的音符反馈以实时发光端为起点。

### 4.8 手柄反馈

| 事件 | 震动参数 |
|---|---|
| 正确轻拍 | `60ms`，弱马达 `0.25`、强马达 `0.08` |
| 正确重拍 | `130ms`，弱马达 `0.65`、强马达 `0.90` |
| 成功闪避 | `90ms`，弱马达 `0.45`、强马达 `0.35` |
| 错误输入 / 闪避失败 | 不震动 |

震动通过浏览器 `GamepadHapticActuator.playEffect('dual-rumble')` 调用；无执行器或调用被浏览器拒绝时不影响操作。

### 4.9 工程与发布

- 开发分支：`dev-1.0`。
- 本地运行：Node.js 20 以上，执行 `npm ci`、`npm run dev`，访问 `http://localhost:5173/`。
- 生产构建：`npm run build`，产物目录为 `dist/`。
- 在线地址：`https://cj-viewer.github.io/MusicGameDemo/`。
- 仓库 Pages 当前发布源为 `gh-pages` 分支根目录；`main` 推送后由 GitHub Actions 自动构建并更新该分支，`dev-1.0` 推送不自动部署，可手动 `workflow_dispatch`。工作流不得把 `dist/` 提交回开发分支。
- Vite `base` 为 `./`，运行时资源使用 `import.meta.env.BASE_URL`，禁止重新写死 `/assets/...` 根路径。
- 运行时资源统一放在 `public/assets/<类型>/` 子目录下，命名、格式与上传流程见 README「资源与资产上传规则」。正式 NPC 动作路径固定为 `images/characters/npc/<角色>/<动作>/`，正式玩家继续使用既有 `images/characters/player/animation/<动作>/`；完整清单见 `docs/美术资产索引.md`。
- 加载分层：`src/game/assetManifest.ts` 是唯一的游戏 core 资源加载清单来源。`queueCoreAssets()` 当前排队 144 张图片、两条节拍音效与教学 BGM，共 147 个 Loader 项、`13,069,079` 字节（约 `12.46MiB`），由 `IntroScene` 在片头播放期间预热、`MainScene.preload()` 兜底；图片中含 37 张环境运行资源与 8 张教学 UI。`pink-stage-clean-background.png`、旧 `arena.png` 与 10 张演唱会候选图不请求，`bg1.psd` 也不是浏览器运行时资源。`queueDeferredBgm()` 为正式关卡 BGM，由 `MainScene.create()` 后台下载；新增游戏内运行时资源必须进入清单，不得直接写回 `MainScene.preload()`。开场标题插画与两段片头由 `IntroScene.preload()` 单独加载，不计入 core。
- `intro.mp4` 与 `intro-rocket.mp4` 都必须为 `1920 x 1080` 且 `moov` 前置（`ffmpeg -movflags +faststart`，或对已有文件执行 `node scripts/faststart-mp4.mjs <文件>`），否则浏览器需整包下载才能起播。BGM 必须是真 MP3，禁止用 `.mp3` 扩展名承载 FLAC 等无损格式。

## 6. 跨系统实现约束

后续修改必须同时检查以下关系：

1. 修改武器 `pattern` 时，必须同时验证节拍提示音、HUD 节奏块、主动输入和轻重攻击方向；换武器不得重新启用自动演示。
2. 修改弹丸寿命时，优先使用 `Conductor` 的拍位置，不要用独立墙钟模拟整数拍规则；警棍默认 `150ms` 并受 P 调参面板的飞行速度倍率缩放。
3. 修改攻击数量时，必须分别检查正确输入、错误输入和 Fever 附加攻击，并确认换武器不会自动发射。
4. 修改玩家自动瞄准时，必须以最后一次有效移动方向作为前方扇区中心；扇区总角度 `45°`，内部目标的有效距离为实际距离一半，不得用上一帧锁定角递归选敌。
5. 修改警棍轨迹时，画面弧段与透明物理命中框必须同步销毁，避免残留 Graphics 或幽灵碰撞体。
6. 修改移动手感时，闪避必须仍以当前按键方向为准，而不是速度惯性方向或鼠标方向。
7. 新增节拍音效时，必须明确是否进入优先级队列；进入队列的事件必须说明同拍冲突顺序。
8. 玩家正式棍状武器必须使用透明内容握把末端作为旋转原点，世界旋转轴固定在角色腰部中线；武器必须保持 `flipX=false`，另一朝向只允许使用负 `scaleX` 几何镜像并同步反转挥击角，不得使用独立侧移。荧光棒直射必须先读取源图发光端经同一套镜像 / 旋转变换后的世界坐标，再沿每条弹道前移内部 `28.8px`；亮芯与三点判定段必须共用此前置起点，不得再用角色固定偏移近似。荧光棒不得恢复角色侧边双环或白色方向楔形。不得恢复程序矩形棒或攻击方向指示线；轻 / 重挥击默认 `200ms`，并随对应攻击速度倍率缩放。
9. 修改节拍采样或响度时，必须同时验证提前输入和延后输入；已有采样应优先调整同一个声音实例，避免无意义叠音。
10. 修改指数波次数量或混编比例时，必须检查出生点分布、碰撞性能，以及警棍和荧光棒的掉落去重。
11. 修改任何当前玩法、参数、素材或输入后，必须同步更新 README、简化原型文档和本记录；完整版策划案的当前快照也必须保持一致。

## 8. 后续更新模板

每次 Vibe Coding 修改后，在“当日调整记录”末尾追加：

```md
### YYYY-MM-DD / 调整主题

- 需求：修改了什么规则。
- 实现：修改了哪些文件和核心参数。
- 兼容：对节拍、输入、弹幕、音效、HUD、素材的影响。
- 验证：执行的构建命令和实际试玩结果。
- 遗留：仍未实现或需要策划确认的内容。
```

不要只记录“优化手感”“调整表现”等模糊描述；必须写明数值、方向、寿命、触发时机和冲突规则。
