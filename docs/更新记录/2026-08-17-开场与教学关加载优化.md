# 2026-08-17：开场与教学关加载优化

## 需求

- 远端部署后，开场动画起播慢、进入教学关等待久，需要针对这两段加载做优化。

## 问题定位

- `intro.mp4` 的 `moov` 原子位于 `mdat` 之后，浏览器必须下完整个 28.5MB 才能开始解码，"点开始"到"出画面"之间是整包下载时间。
- `intro.mp4` 为 2560×1440 / 约 15.6Mbps，而游戏内部画布只有 1920×1080，一半以上的像素与码率被浪费。
- `bgm1.mp3` 实际是 **FLAC 编码**（扩展名为 `.mp3`），206 秒占 24.66MB；其余三首是约 190kbps 的真 MP3。
- `MainScene.preload()` 一次性排队全部四首 BGM（合计约 40MB），但教学关只用到 `bgm-0`（`DEFAULT_TUTORIAL_BGM_SLOT = 3`），`bgm-1` 要到正式关卡才需要。
- 片头播放的 15 秒完全没有用于预热后续资源，`MainScene` 的贴图要等片头结束后才开始下载。

## 实现

### 资源

- `intro.mp4` 重编码为 1920×1080 / H.264 CRF 23 / AAC 128k，并加 `-movflags +faststart`：28.53MB → 5.55MB，`moov` 前置。
- `bgm1.mp3` 由 FLAC 重编码为 190kbps VBR 的真 MP3 并剥离封面图：24.66MB → 4.70MB。
- 新增 `scripts/faststart-mp4.mjs`：无需 ffmpeg 即可把 MP4 的 `moov` 无损前移（同时修正 `stco`/`co64` 的 chunk 偏移），供后续更换片头时快速处理。

### 加载策略

- 新增 `src/game/bgmTracks.ts`：从 `MainScene` 抽出 `BgmTrack`、`BGM_TRACKS` 与两个默认槽位常量，供加载清单复用。
- 新增 `src/game/assetManifest.ts`：`queueCoreAssets()` 排队全部贴图、打击音效与教学关 BGM；`queueDeferredBgm()` 排队其余三首；`startBackgroundLoad()` 在不打断当前 Scene 的前提下启动 Loader。
- `IntroScene` 在片头真正开始播放（`VIDEO_PLAYING`）时调用 `warmGameAssets()`，用这 15 秒把 `MainScene` 的资源预热进全局缓存；玩家一直停在标题页时由 5 秒延时兜底触发。片头缓冲期间显示"缓冲中…"。
- `MainScene.preload()` 改为只调用 `queueCoreAssets()`，并新增进度条，避免远端首次加载时是纯黑屏。正式关卡的三首 BGM 改在 `create()` 里后台下载。
- `switchBgmTrack()` 在目标曲目尚未就绪时不再阻塞：记录到 `pendingBgmSwitch`、把该曲目提到加载队列前面，当前曲目继续播放；`onDeferredFileComplete()` 在文件到位后补完切歌。

## 影响

- 进入教学关前的阻塞下载量：约 68MB → **11.56MB**（片头 5.55MB + 贴图 2.53MB + 音效 0.04MB + 教学 BGM 3.44MB）。
- 片头可边下边播，不再需要整包下载；实测 `loadedmetadata` 10ms、`canplay` 23ms。
- 片头播放期间即完成 `MainScene` 资源预热，片头结束后 `MainScene.preload()` 排队文件数为 0，直接进入教学关。
- 其余 15.27MB 的 BGM 转入后台下载，不再阻塞教学关。

## 验证

- `npm run build` 通过（`tsc --noEmit` 无错误）。
- 片头视频：`loadedmetadata` 10ms / `canplay` 23ms，时长 15.12s，分辨率 1920×1080；`moov` 已位于 `mdat` 之前。
- 画质：对 1080p 参考源做 VMAF，CRF 23 中位数 94.6（CRF 20 为 95.7，但体积大 34%）。
- `bgm1.mp3` 重编码前后用浏览器 `decodeAudioData` 交叉相关：样本数同为 9,087,643，**对齐偏移 0 样本**，分段 RMS 最大偏差 0.008dB，因此 `firstBeatOffset: 0.012` 无需调整，节奏不会偏拍。
- 运行时：片头预热后缓存为 104 张贴图 + `beat-light` / `beat-heavy` / `bgm-0`，`totalFailed = 0`；跳过片头后 `MainScene` 待加载数为 0，状态直接进入 `tutorial` 且 `bgm-0` 正在播放；后台补下 `bgm-1` / `bgm-2` / `bgm-3` 完成后无失败。
- 延迟切歌路径：在 `bgm-1` 未就绪时请求切歌，`bgm-0` 继续播放且记录 `pendingBgmSwitch`；文件到位后自动切到 `bgm-1` 并播放，`pendingBgmSwitch` 清空。
- 与 `008df2c`「跳过教学」合并后复测最坏路径：连续「空格跳过片头 → 空格跳过教学」时 `bgm-1` 必然未就绪，实测状态进入 `intermission`、`bgm-0` 无缝续放且 `pendingBgmSwitch = bgm-1`；文件到位后自动切换为 `bgm-1`，播放倍率 `0.9103`（`132 / 145`），`totalFailed = 0`，玩家状态正常。

## 遗留

- `public/assets/images/backgrounds/arena.png`（2.5MB）在 `src/` 中无任何引用，会被打包部署但浏览器从不请求。本次按要求保留。
- `bgm0` / `bgm2` / `bgm3` 各含约 25KB 的封面图（MJPEG 流），体积占比极小，未处理。
- 原 `bgm1` 的 FLAC 数据本身存在一处解码错误（`invalid sync code`），重编码前后同样存在，未影响时长与样本数。
