# 2026-08-18：正式关物件真实底边锚定

## 需求

修复正式关指定物件在轻 / 重拍缩放回弹时，主体底部短暂露出浅色或白色缝隙的问题。物件仍可按拍回弹，但脚底、接触影和地面接缝必须保持稳定。

## 实现

- 根因是部分 RGBA 物件在可见主体下方保留了透明安全边；旧实现直接以整张 PNG 的画布底边作为 `Origin`，缩放时会把真实主体底边向上拉离原位置。
- `scripts/rebuild_pink_stage_layers.py` 现在从每张输出 PNG 的 Alpha bbox 读取真实可见底边，并把 `visibleBottom` 写入 `pinkStageProps.generated.ts`。
- `PinkStageEnvironment` 使用 `visibleBottom / height` 作为 Y Origin，同时把初始 Y 改为 `prop.y + visibleBottom`。静止帧的原始左上坐标、显示尺寸和重组结果保持不变；补间缩放时真实可见底边固定不动。
- 顶部粒子花的位置改为按自定义 Origin 反算纹理顶边，继续贴合原物件顶部。

## 影响

只修正 35 张正式环境物件的生成元数据和回弹锚点。最终 17 个白名单物件的回弹倍率、时长、缓动、粒子花、坐标、深度与资源不变；中央人物 / 左右栏杆 `21 / 23 / 24` 按后续反馈停止回弹，连同另外 15 个非名单物件、运行底图、碰撞、节拍、镜头、角色、HUD、攻击和玩法逻辑均不改变，也没有新增运行时资源。

## 验证

- `npm.cmd run build` 与 `git diff --check` 通过；35 个 `visibleBottom` 已逐张与实际 PNG Alpha bbox 核对，缺失或不一致为 `0`。
- 在 `http://127.0.0.1:5180/` 硬刷新并经 `R` 重开后进入正式关，在倒计时阶段连续抓取 `48` 帧，覆盖多个轻 / 重拍补间。中央栏杆、左侧标牌 / 箱体 /石块和底部立柱 / 罐体均发生预期回弹，但其接触底边以下的像素行保持不变；纯底图区逐通道变化为 `0`，未再观察到露白缝。
- 浏览器控制台为 `0 error / 0 warning`。

## 遗留

以后重新抠图或运行分层脚本时，必须同步生成并复核 `visibleBottom`；不得手工把 Origin 恢复为整张透明画布的底边。
