# 2026-08-17：增加火箭片头并校正预载口径

## 需求

合入 `upstream/dev-1.0` 新增的第二段火箭片头，使开场按 `intro.mp4 → intro-rocket.mp4 → 教学` 顺序播放，并在提交前完成视频与加载清单验收。

## 实现

- `IntroScene` 同时加载两段视频；第一段正常结束后在同一个、已经由玩家点击解锁的 Video GameObject 上通过 `changeSource()` 切换到 `intro-rocket.mp4`，避免第二个有声媒体元素被浏览器再次拦截。第二段完成后进入教学；标题页或任一段播放期间按 `Space` 都会跳过全部片头。
- 将上游新增的 `intro-rocket.mp4` 从 `2560 x 1440` 重编码为 `1920 x 1080` H.264 + AAC、CRF `23`，并把 `moov` 前置。时长约 `10.14s`，文件为 `6,652,395` 字节，SHA-256 为 `2F23CE99464DB0712916074B4A7DE08116B5C4315119FD318B87C24137454A38`。
- 精确复算 `queueCoreAssets()`：当前为 `137` 张图片、两条节拍音效与教学 BGM，共 `140` 个 Loader 项、`12,977,685` 字节（约 `12.38MiB`）。两段片头由 `IntroScene` 单独加载，不计入 core。

## 影响

- 正常观看时会连续播放两段有声片头；空格跳过、片头期间预热 MainScene 资源和进入教学的场景切换保持有效。
- `intro.mp4` 继续保持 `1920 x 1080`、`5,824,033` 字节与 `moov` 前置；两段视频合计约 `11.90MiB`，不改变 140 个 core Loader 项。
- 本次同时修正文档中把音频、图片和运行时程序纹理混写为“142 个预载纹理键”的旧口径。

## 验证

- `npm.cmd run build` 通过。
- 浏览器从标题页开始完整观看，确认 `intro.mp4` 自动切换到火箭片头，火箭片头结束后进入教学；标题页与视频播放期间的 `Space` 跳过均已分别复测。
- 两段视频均为 `1920 x 1080`，顶层 MP4 原子中 `moov` 均位于 `mdat` 前；本地页面、两段视频、教学 UI 与池塘背景资源均返回 HTTP `200`，浏览器控制台为 `0 error / 0 warning`。

## 遗留

两段项目方片头的公开发布权属仍需项目方持续确认；后续替换任一视频都必须重新执行分辨率、编码、`moov` 与浏览器播放验收。
