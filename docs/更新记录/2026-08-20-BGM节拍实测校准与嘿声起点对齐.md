# 2026-08-20：BGM 节拍交叉校准与嘿声起点对齐

## 需求

- 鼓点和音乐的节奏对不上；要求用脚本检测各音频实际发声时刻后精准对齐，而不是直接按文件时间轴播放（单个音效文件存在前置延时）。

## 背景与方法

背景鼓点由 WebAudio 振荡器在 Conductor 拍点上采样级精确发声，音乐靠 `bgmTracks.ts` 的 `sourceBpm` / `firstBeatOffset` 换算播放倍率对齐到同一网格；`sourceBpm` 的相对误差会随播放逐拍累积成可听漂移。

新增 `scripts/measure_audio_timing.py`（依赖 ffmpeg + numpy）：解码后对全曲 onset 包络做 (BPM, 相位) 网格搜索。关键检验是**八段相位平整性**：固定候选 BPM 把全曲分八段分别估相位，只有相位不随时间漂移的 BPM 才是真值。早期版本用四段 ±50ms 窗口曾把 bgm2 误测为 175.059，加宽窗口后修正——这也是把检验方法写进脚本和曲目表注释的原因。

本轮与 dev-1.0 上同日的「教学对白扩写、BGM 重测与 Victory 冻结」（3.113，bgm0 `153.04/0.245`、bgm2 `174.002/0.231`）互为交叉验证，八段检验的结论是**双方各对一半**：

| 曲目 | 3.113 值 | 本轮实测 | 八段检验结论 |
|---|---|---|---|
| bgm0 BPM | 153.04 | **153.057** | 153.057 相位平整（-0.008→0.002）；153.04 摆动 0.18~0.30 |
| bgm0 首拍 | 0.245 | **0.0** | 开头强拍 0.382 / 0.766 落在 0.0 网格 ±20ms 内 |
| bgm2 BPM | **174.002** | 174.003 | 174.002 相位完全平整（0.189±0.002）；旧测 175.059 在宽窗下明显摆动 |
| bgm2 首拍 | 0.231 | **0.19** | 174.002 下八段相位一致收敛于 0.189~0.191 |

bgm1 / bgm3 的 BPM 准确（145.0005 / 146.3173），首拍按统一测量口径小幅收紧为 `0.0 / 0.02`。

"嘿"声采样：light 响度峰值在文件 `0.133s`（旧 seek `0.105` = 峰前 28ms，合理）；heavy 峰值在 `0.187s`、起声爬升长达 115ms（旧 seek `0.11` = 峰前 **77ms**，重音明显晚于输入）。

## 实现

- 新增 `scripts/measure_audio_timing.py`：SFX 报告 -40/-30/-20dB 起声、最陡上升与峰值；BGM 做 BPM/相位网格搜索与分段相位验证。
- `src/game/bgmTracks.ts`：bgm0 `sourceBpm 153.04→153.057`、`firstBeatOffset 0.245→0.0`；bgm2 保留 `174.002`、`firstBeatOffset 0.231→0.19`；bgm1 `0.012→0.0`；bgm3 `0.026→0.02`；`loopBeats` 维持 3.113 的 `436 / 616`（与修正后 BPM 按 `round(时长×BPM/60)` 口径一致）。
- `src/core/Conductor.ts`：seek 规则统一为"实测峰值前 30ms"——`LIGHT_CALL_START 0.105→0.103`、`HEAVY_CALL_START 0.11→0.157`；重声淡出换算到新播放轴（`0.33/0.36→0.283/0.313`，等效文件位置 0.44~0.47s 不变）。

## 影响

- 教学关音乐不再漂移（3.113 的 153.04 每拍残余约 0.03ms，曲末约 30ms，本轮归零到八段检验分辨率内）；bgm0 首拍锚回正拍（0.245 为 0.625 拍偏移，开头强拍全部对不上）。
- 正式关（bgm2）拍锚提前 41ms 到实测收敛值。重攻击"嘿"的听感重音提前 47ms，更贴近输入。
- 判定逻辑不变：判定窗口一直以 Conductor 网格为准，本次只是让音乐真正贴上该网格。
- **注意**：P Menu 的「正式关节拍对齐偏移」会持久化到 localStorage；此前为补偿旧相位手动调过该值的测试者应把它归零后再试听。

## 验证

- 浏览器 `decodeAudioData` 与 ffmpeg 解码逐毫秒一致（bgm0/bgm2 开头 onset 序列与时长完全相同），脚本测量值对运行时有效。
- 八段相位平整性：bgm0@153.057 = [-0.008…0.002]，bgm2@174.002 = [0.189…0.191]，两条曲线均无趋势性漂移。
- 实跑：教学关速率 `132/153.057`；音乐位置换算拍相位与 Conductor 拍相位连续采样差值 `0.0000` 拍；延迟切歌到 bgm-2 正常；`playPlayerCall('L'/'H')` 无异常；控制台无 error；`npm run build` 通过。

## 遗留

- 曲目表与脚本注释已写明：改动 BGM 前必须重跑 `scripts/measure_audio_timing.py` 并通过八段相位检验，禁止手填估算值。
- 不同输出设备的系统性音频延迟仍由 P Menu 的对齐偏移做主观微调（应在归零基础上调整）。
