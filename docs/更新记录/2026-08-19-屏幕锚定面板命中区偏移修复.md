# 2026-08-19：屏幕锚定面板命中区偏移修复

## 需求

- Esc 音量设置面板的滑块 / 按钮需要把鼠标放到偏上偏左的位置才能按到，拖动进度条手感错位；P 调参面板的按钮存在同样问题。

## 实现

- 根因：屏幕锚定容器（音量面板、P 面板及其嵌套分页容器）设置了 `scrollFactor(0)`，但容器内的交互子对象自身 `scrollFactor` 仍为默认 `1`。Phaser 渲染时把子对象与容器的 scrollFactor 相乘（`1 × 0 = 0`，位置正确），而 `InputManager.hitTest` 只读取子对象自身的 scrollFactor，导致命中区整体偏移一个相机 scroll：基础相机 scroll 为 `(78.1, 43.9)` 世界单位，换算到 2K 屏幕约 `(84, 47)px`，并随镜头前探继续漂移。
- 新增 `cameraConfig.applyScreenLayerScrollFactor(container)`：递归把容器及全部后代（含嵌套容器）的 scrollFactor 置 0。
- `MainScene.createSettingsPanel` 在音量面板容器创建后、以及向 `tuningEditor.container` 追加分页容器与按钮后各调用一次；`TuningEditor` 构造时也改为调用该辅助函数。
- 无视觉变化，不改任何坐标、尺寸或玩法参数。

## 影响

- 音量面板九路滑杆、FPV 开关、P 面板四个分页标签、分页内 ± 步进按钮与 BGM Slot 按钮均在视觉位置命中。
- 镜头前探时命中区不再随 scroll 漂移。

## 验证

- `npm run build` 通过 TypeScript 检查与 Vite 生产构建。
- 实机用 Phaser `hitTest` 全屏扫描：主音量 / BGM / 敌人死亡音效滑块命中中心与视觉位置误差 ≤ 2px（扫描步长 4px），FPV 开关按钮命中框 `256 x 64` 与视觉一致；修复前命中中心实测为视觉位置左上 `(84, 47)px`。
- 真实鼠标事件在主音量滑块视觉位置按下并左拖 60px，主音量由 `100%` 变为 `50%`；旧偏移位置不再命中。
- P 面板打开后，分页标签、嵌套 ± 按钮与自有按钮均在视觉位置命中，旧偏移位置不再命中。

## 遗留

- 后续任何新建的屏幕锚定交互容器（`scrollFactor(0)` + 子对象 `setInteractive`）都必须在子对象添加完毕后调用 `applyScreenLayerScrollFactor`，否则会复现同类偏移；已写入跨系统实现约束。
