# 2026-08-12：叫喊与 BGM 循环校准

## 需求

- 补偿轻、重叫喊素材的前置起声，并缩短重叫喊尾音。
- 解决 BGM 原生循环造成的节拍漂移。
- 收紧攻击判定窗口，并让所有节拍叫喊保持统一音量。

## 实现

- 轻、重叫喊分别提前 `70ms / 74ms` 播放；调度前视范围提高到 `220ms`。
- 重叫喊在素材时间 `330–360ms` 使用 WebAudio 增益淡出，源 MP3 保持不变。
- 节拍叫喊固定使用音量 `0.16`，删除正确输入按拍位提高音量的逻辑。
- BGM 关闭原生循环，改为每 `616` 拍（`154` 个四拍小节）按 Conductor 重新对齐播放。
- 攻击窗口由拍点前后各 `0.2s` 调整为各 `0.1s`；闪避窗口不变。

## 影响

- 叫喊的有效起声更接近拍点，重叫喊不再覆盖下一拍；正确输入通过攻击、Combo、震动和画面反馈表现，不再通过叫喊音量区分。
- 当前 BGM 每轮约 `43.5ms` 的非整拍差值在循环边界等待补齐，不会逐轮累计。
- 攻击有效窗口由每拍共 `400ms` 缩短为 `200ms`，节拍要求更明确。

## 验证

- `npm run build` 已通过 TypeScript 检查与 Vite 生产构建。
- 代码检查确认 BGM 为非原生循环，叫喊音量不再读取正确输入状态。
- 本地页面返回 HTTP 200；点击开始后浏览器控制台无 error / warn。

## 遗留

- 需人工试听轻、重叫喊的主观贴拍程度，以及首次 `616` 拍循环边界的听感；如素材继续替换，提前量和淡出点必须重新测量。
