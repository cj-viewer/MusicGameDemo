# 2026-08-10：粉丝敌人动画与节拍突进

## 需求

- 导入用户提供的粉丝跑步、翻滚、近战序列帧。
- 慢行播放跑步，拍前突进播放翻滚，攻击时播放近战。
- 素材默认朝右，敌人向左时由引擎翻转。
- 粉丝显示尺寸提升为原来的 `1.25x`；突进距离提高为旧实现约两倍。
- 跑步只保留 `02–05` 四帧，剔除未使用的 `01`、`06`。

## 实现

- 新资源位于 `public/assets/images/characters/fan/{run,roll,attack}/`。
- `MainScene` 按动作预加载帧，并注册 `fan-run`、`fan-roll`、`fan-attack` 三个 Phaser 动画。
- `fan-run` 只使用 `run-02.png` 至 `run-05.png`；翻滚与近战均使用各自 `01–06` 帧。
- `FanEnemy` 改为 Sprite，慢行尺寸为 `60 × 95px`（此前 `48 × 76px`）。
- 水平速度为负时执行 `setFlipX(true)`；慢行播放跑步、拍前 `0.1s` 的高速度状态播放翻滚、每小节攻击播放一次近战。
- 粉丝拍前速度为 `210 px/s`，并配套提高加速度，使该 `0.1s` 窗口的位移约为旧 `105 px/s` / `650 px/s²` 实现的两倍。

## 影响

- 保留粉丝的 `40 HP`、`17px` 碰撞半径、每小节单发蓝色弹丸和荧光棒掉落规则。
- 不改变保安的移动、攻击或视觉逻辑。
- 已删除运行时不再使用的 `run-01.png`、`run-06.png`；跑步目录仅保留 `02–05`。

## 验证

- `npm.cmd run build` 通过 TypeScript 检查和 Vite 生产构建。
- 在 Codex 内置浏览器打开本地开发服务器，页面标题正常、控制台无运行时 error。

## 遗留

- 自动化环境已验证资源加载与无报错；粉丝在密集波次下的画面可读性、实际体感距离仍建议在人工试玩中确认。
