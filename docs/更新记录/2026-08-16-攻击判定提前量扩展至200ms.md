# 2026-08-16：攻击判定提前量扩展至 200ms

## 需求

让玩家攻击可在目标拍点前 `200ms` 提前输入，降低提前按键的失败率。

## 实现

- 攻击判定由对称的前后各 `100ms` 改为不对称窗口：拍前 `200ms`、拍后 `100ms`。
- 教学自动演示、正式攻击和输入延迟校准后的判定共用同一窗口函数，单拍仍最多结算一次输入。
- 重拍律动条的橙色预告保持 `200ms` 过渡，但整体前移为拍前 `400ms → 200ms`，在攻击窗口开启时完成转橙。
- 场地内框的尺寸扩散也读取同一 `INPUT_EARLY_WINDOW`：未来三拍仍同时预告，但单框周期由 `3` 拍缩短为 `2.4` 拍（晚 `20%` 出现、平均速度 `1.25x`）；以单条归一化指数曲线动态校准曲线强度，使框在拍前 `200ms`、到 `0.85x` 时可攻击，并连续加速到 `1x` 边界；不再在窗口起点拼接两段曲线。

## 影响

- 在 `132 BPM` 下，一拍约 `455ms`；攻击窗口总长 `300ms`，约占一拍 `66%`，其中提前段约占一拍 `44%`。
- 拍后宽限、闪避判定（前后各 `120ms`）、伤害、Combo 和 BGM 同步均不改变。
- 后续若调整攻击提前窗口，归一化曲线强度会随 `INPUT_EARLY_WINDOW` 自动重算，不会再出现视觉节奏与判定时间脱节或窗口起点速度突变。

## 验证

- 运行 `npm.cmd run build`。
- 手动确认拍前 `200ms` 的轻/重攻击正确结算，早于 `200ms` 或晚于 `100ms` 的输入仍判错；重拍律动条在拍前 `400ms → 200ms` 完成转橙；每个场地内框在拍前 `200ms` 时为 `0.85x`，之后从慢到快连续抵达边界拍点、没有速度换挡。

## 遗留

- 本次未改变保音高 BGM 预处理策略；实时降速时的音高变化仍保留供试听评估。
