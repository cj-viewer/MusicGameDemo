# 2026-08-15：重拍判定窗前 0.2 秒转橙

## 需求

- 周围律动条只在橙色正确判定输入窗口开始前 `0.2s` 内过渡到橙色。

## 实现

- 将律动条的颜色预告从原有压缩蓄力进度中拆出，压缩和跳动时序保持不变。
- 下一拍为轻拍时，律动条始终保持原有粉紫色。
- 下一拍为重拍时，律动条先保持粉紫色；当前正确判定窗口为拍点前后各 `0.1s`，因此从拍点前 `0.3s` 开始转色，在拍点前 `0.1s`、也就是判定窗开启时完成转橙，并保持到重拍落点。
- 各条原有随机延迟继续保留，但被限制在同一个 `0.2s` 转色区间内，所有条都会在窗口开启时完成过渡。

## 影响

- 只改变三侧律动条的重拍转色时间。
- 不改变判定窗口、律动条压缩 / 跳高、明度 / 饱和度上限、不透明度、TopDown 排序或碰撞规则。

## 验证

- `git diff --check` 通过。
- `npm.cmd run build` 通过。
- 本地浏览器连续截图复核轻拍保持粉紫色、重拍只在指定短区间转橙，两个重拍转色段之间均完整恢复粉紫，页面持续运行正常。

## 遗留

- 无。
