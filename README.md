# MusicGameDemo

基于 **Phaser 4 + Vite + TypeScript** 的 2D 音乐弹幕游戏原型。当前原型验证“自由走位 + 固定节拍攻击 + 轻重连段 + 节拍弹幕”的战斗循环。

- 在线试玩：[cj-viewer.github.io/MusicGameDemo](https://cj-viewer.github.io/MusicGameDemo/)
- 开发分支：`dev-1.0`
- 生产 Pages：推送 `main` 自动部署；`dev-1.0` 可通过 GitHub Actions 手动部署。

## 快速开始

```powershell
git clone --branch dev-1.0 https://github.com/cj-viewer/MusicGameDemo.git
Set-Location MusicGameDemo
npm ci
npm run dev
```

默认访问 <http://localhost:5173>；点击画面开始游戏并解锁浏览器音频。端口被占用时可指定其他端口，例如：

```powershell
npm run dev -- --host 127.0.0.1 --port 3000
```

| 指令 | 用途 |
|---|---|
| `npm ci` | 按锁定文件安装依赖 |
| `npm run dev` | 启动带热更新的开发服务器 |
| `npm run build` | TypeScript 检查并构建到 `dist/` |
| `npm run preview` | 本地预览生产构建 |

## 操作

| 输入 | 行为 |
|---|---|
| `W A S D` | 带惯性的八向移动 |
| 鼠标 | 瞄准；前方 `90°` 内自动辅助瞄准最近敌人 |
| 鼠标左键 / 右键 | 轻攻击 / 重攻击（均需踩节拍） |
| `Shift` | 沿当前移动方向闪避 |
| `Esc` | 打开 / 关闭设置面板；打开时游戏完全暂停，可调主音量和右侧伪 3D 第三人称视口 |
| 左 / 右摇杆 | 移动 / 瞄准 |
| `LB` / `RB` | 闪避 / 自动按当前节拍提交轻或重攻击 |
| `R` / `F` | 重新开始 / 调试时直接充满 ComboMeter |

## 当前原型快照

- `146.32 BPM`、`4/4`；攻击判定窗口为拍点前后各 `0.1s`。`bgm3.mp3` 的首拍偏移为文件内 `0.026s`，启动及每 616 拍循环时都与节拍时钟重新对齐。
- 页面采用横向双联屏：左侧俯视主视口与右侧伪 3D 第三人称视口均为 `1280 x 720`、严格 `16:9`，组合逻辑画布为 `2560 x 720`。页面继续用 `FIT` 等比缩放，因此不会拉伸任一视角；普通 16:9 显示器上会在上下保留黑边。右侧只读，不响应攻击或标题点击，鼠标移入右侧也不会改变左侧瞄准。
- 右侧以草地演唱会为主题，用程序绘制舞台、草地与透视路径；玩家、敌人、场地立柱和弹幕复用主场景 2D 数据，按距离透视缩放与遮挡。角色以白色剪影描边、脚底支架和接地阴影形成童话绘本式立牌，视觉碰撞关系来自左侧真实物理坐标，不另建第二套玩法状态。
- 默认主音量为 `150%`，仅能通过 `Esc` 打开的设置面板在 `0–300%` 范围内调整；面板打开时会暂停节拍时钟、BGM、物理、动画、补间和输入推进。面板同时可开关右侧等大的只读第三人称视口；观察方向严格跟随主视口内的鼠标原始瞄准方向，不会被辅助瞄准锁敌带偏。BGM 基础音量为 `0.3`，轻、重节拍叫喊基础音量均为 `0.28`，程序合成音效也统一经过主音量。素材分别提前 `70ms / 74ms` 播放，重叫喊在素材时间 `330–360ms` 淡出。
- 战斗区为 `1092 x 614px`，相对屏幕左、右、下各预留约 `82px` 的人群律动带。约 140 根完全不透明的深紫粉竖条沿三侧按交错轨道铺开：底部两轨保留横向 `±5px`、纵向 `±4px` 的错落，左右三列保留横向 `±4px`、纵向 `±2.5px` 的错落，既有随机人群感也不会大面积完全重叠。律动条没有碰撞盒，可在跳动时侵入战斗区；轻重拍的明度提升和饱和度降低均不超过 `5%`。
- 律动条与角色 Sprite / Image 统一按脚底 Y 做 TopDown 遮挡：越靠屏幕下方越晚绘制并遮住上方对象；玩家手持武器、瞄准线和敌人血条跟随所属角色深度。
- HP 血条移至左下并与 ComboMeter 处于同一水平基线；Combo 环另向右移动其自身宽度的一半（`22px`），仍保持更明显的同拍律动：轻拍前纵向压至 `0.84x`、拍点弹至 `1.26x`；重拍前压至 `0.62x`、拍点弹至 `1.50x`。只改变厚度和最多 `5%` 的明度 / 饱和度，血量长度与数字保持稳定。
- 战斗区内角色、碰撞体、手持武器、掉落、敌我弹幕和对应场内特效统一缩放至上一版的 `0.8x`；HUD、场地、节奏条与边缘律动带不缩放。圆形表盘标题常驻显示 `ComboMeter`。
- 教学与正式游戏统一使用场地判定框：底部汇聚式节奏条均不显示，教学仍保留顶部四拍连段和延迟校准。三个场地内框同时预览未来 `1 / 2 / 3` 拍：每框从场地 `0.7x` 且完全透明的状态出发，在 `3` 拍内按 `easeInExpo` 同步扩大和淡入，到达边界即为拍点并立即隐藏，绝不显示到场地框外。轻拍使用低饱和粉紫 `#e879f9`，重拍使用橙色 `#f97316`；正确输入会额外让本拍场地框加粗、轻微外扩并淡出。Fever Time 中每次正确输入额外恢复 `10 HP`，不超过最大生命；踩拍镜头缩放为原先的一半（轻 / 重最大 `1.0075x / 1.015x`）。
- 手持武器为单根短棒，实时跟随鼠标方向并与瞄准短线重合（握把在瞄准线起点）；每次挥击在 `200ms` 内收敛回瞄准线，不再延续到下一拍。荧光棒攻击改为最长 `720px` 的瞬时高亮直光束：命中最近敌人时在其表面截断并快速消失，同时给出轻量光电反馈。
- 五波敌人总数为 `2 / 4 / 8 / 16 / 32`，每波保安与粉丝各半。
- 玩家使用像素女高中生序列帧（Dlou Saiyan 素材，非商用需署名）：待机 2 帧、跑步 4 帧、倒地 1 帧，可见高度约 `63.6px`，瞄准左侧时翻转并随节拍轻微蹲弹；粉丝使用序列帧：慢行跑步 `02–05`，拍前突进和受击使用翻滚，按小节攻击时使用近战。素材默认朝右，向左时由引擎翻转。
- 粉丝动作保持旧静态粉丝的动作占比并统一乘 `0.8x`：跑步、翻滚、近战可见高度约 `58.4 / 54.4 / 65.6px`；同一动作内帧高一致、宽度等比变化。粉丝拍间慢行 `30 px/s`，下一拍前 `0.1s` 的翻滚突进按约两倍旧位移调校。
- 敌方攻击改为与玩家光束完全分开的点状弹幕：每次按前 1、中 2、后 3 发射六点阵列；保安为青白描边胶囊点，粉丝为暖红描边光点，均保留外轮廓且不生成线状拖尾，同屏上限 `240`。

## 网页内实时美术替换

页面右上角的 **美术替换** 按钮可打开本地测试面板，不离开游戏即可替换战斗背景、玩家、保安和粉丝图片。点击“选择图片”或把文件拖到对应卡片后立即生效；当前角色和后续生成敌人都会更新。

- 支持 PNG、JPG、WebP、GIF，单张不超过 `20MB`；每项可单独恢复，也可全部恢复默认。
- 背景按 `1280 x 720` 居中等比覆盖；角色保持当前显示比例和碰撞规则。玩家与粉丝换图期间使用静态预览，恢复默认后继续原序列帧动画。
- 替换只保存在当前浏览器页面的内存中，不上传、不写入项目；按 `R` 重开保留，刷新页面恢复项目默认素材。
- 面板实现位于 `src/game/ArtAssetTool.ts`，场景运行时替换接口位于 `src/scenes/MainScene.ts`。

精确玩法数值与验证范围见 [简化玩法策划案](docs/简化玩法策划案（原型版）.md)。

## 文档入口与维护规则

文档目录的职责和更新顺序见 [docs/README.md](docs/README.md)。各文件不是重复备份：

| 文档 | 用途 |
|---|---|

| [实机落地与调整记录](docs/实机落地与调整记录.md) | 代码事实、精确参数、历史变更和验收清单 |
| [完整策划案](<docs/2D音乐弹幕游戏策划案 (持续更新).md>) | 长期产品目标；不等于已实现内容 |
| [更新记录](docs/更新记录/README.md) | 每次可交付改动的短记录与影响范围 |
| [资源与素材规范](docs/资源与素材规范.md) | 资源目录、命名、加载和验收规则 |
| [AGENTS.md](AGENTS.md) | Agent 进入项目时必须先读的规范、变更合同与验证要求 |

**任何影响玩法、参数、素材、输入、音效、表现、工程入口或部署的改动，必须在同一提交中：**

1. 在 `docs/更新记录/` 新增或更新对应日期的短记录；
2. 更新 `docs/实机落地与调整记录.md` 的“当前实机规则”和验收项；
3. 若玩家可感知规则变化，再同步更新简化玩法策划案；
4. 若改变了长期产品目标，再同步完整策划案。

只改代码、不更新文档，视为改动未完成。
