# MusicGameDemo

> 当前 UI 统一为可爱像素面板风格：教学 / 池塘关使用浅绿底、深青像素描边、青色按钮与清晰深青文字；正式 / 粉紫关使用粉紫底、紫色像素描边与清晰深紫文字。所有 HUD、教学卡、ComboMeter / 武器条、HP、Wave / 四拍提示、Esc 音量面板、P 调参面板、失败提示、FPV 小窗、标题页按钮与双人联机面板只更换样式，不改变输入、判定、音量、联网、暂停、反馈或战斗逻辑。

> 武器名称和连招提示始终读取当前装备数据：持有荧光棒时显示“荧光棒”，切换警棍后显示“警棍”；面板皮肤不会写死任何名称、数值或状态。

基于 **Phaser 4 + Vite + TypeScript** 的 2D 音乐弹幕游戏原型。当前原型验证“自由走位 + 统一鼓点 + 任意拍起手的轻重连招 + 节拍弹幕”的战斗循环。

- 在线试玩：[cj-viewer.github.io/MusicGameDemo](https://cj-viewer.github.io/MusicGameDemo/)
- 开发分支：`dev-1.0`
- 生产 Pages：发布源为 `gh-pages` 分支；推送 `main` 后由 GitHub Actions 自动构建并更新该分支，`dev-1.0` 可通过 Actions 手动部署到同一在线链接。

## 快速开始

```powershell
git clone --branch dev-1.0 https://github.com/cj-viewer/MusicGameDemo.git
Set-Location MusicGameDemo
npm ci
npm run dev
```

默认访问 <http://localhost:5173>；点击画面开始游戏并解锁浏览器音频。端口被占用时可指定其他端口，例如：

```powershell
npm run dev -- --host 127.0.0.1 --port 3000
```

| 指令 | 用途 |
|---|---|
| `npm ci` | 按锁定文件安装依赖 |
| `npm run dev` | 启动带热更新的开发服务器 |
| `npm run build` | TypeScript 检查并构建到 `dist/` |
| `npm run preview` | 本地预览生产构建 |

## 双人联机

标题页可选择“单人模式”继续原有剧情 / 波次流程，或选择“多人联机”进入房间大厅。联机需要同时运行网页服务器与 WebSocket 服务器：

    npm run multiplayer:server
    # 另开终端
    npm run dev

房主创建 5 位房间码并固定使用警棍；第二位玩家输入房间码加入并固定使用荧光棒。双方均为真人、各有独立 100 HP 血条，不生成 AI。移动支持方向键 / WASD，Z/J 轻击、X/K 重击；攻击需落在 132 BPM 拍点前后 190ms 内。房间服务器负责命中、伤害和胜负判定。部署到 HTTPS 页面时，需用 VITE_MULTIPLAYER_WS_URL=wss://你的服务器地址 指向单独部署的 WebSocket 服务；GitHub Pages 本身只托管静态网页。
## 操作

| 输入 | 行为 |
|---|---|
| `W A S D` | 带惯性的八向移动；突然反向时立即清零原速度并向新方向起步 |
| 自动 / 手动瞄准 | 默认自动锁定综合优先级最高的敌人；P Menu“模式 / 导出”可开启手动瞄准，开启后角色脚下显示跟随鼠标方向旋转的三角箭头 |
| 鼠标左键 / `"` 键 | 轻攻击（需踩节拍）；手动瞄准时沿箭头方向攻击 |
| 鼠标右键 / `Enter` | 重攻击（需踩节拍）；警棍可长按连续发射弧形光波，四拍连招的第 2 拍按下、第 3 拍松开 |
| 左 `Shift` / 右 `Shift` | 沿当前移动方向闪避 |
| `Esc` | 打开 / 关闭浅色磨砂白线音量面板；打开时游戏完全暂停，可调主音量、BGM、节拍与轻重喊声，并开关右下 FPV 观察窗；P 面板打开时按 Esc 会直接切换到音量面板 |
| 左摇杆 | 移动；右摇杆不再控制瞄准 |
| `LB` / `RB` | 闪避 / 自动提交当前连招所需输入（空闲时始终为轻攻击起手） |
| `R` / `F` | 重新开始 / 调试时直接充满 ComboMeter |
| `P` | 打开六页调参面板；可调整玩家 / 敌人 / Boss 战斗参数、ComboMeter 奖励、切换两种重击模式，并可持久化保存或导出当前配置 |
| `Space` | 在开场标题页 / 开场视频期间跳过片头；教学期间跳至教学结束动画；动画期间跳过并进入第一关 |

## 当前原型快照

- 内部画布统一为 `2560 x 1440`（2K），Phaser 使用 Nearest Neighbor、`pixelArt` 与整数像素渲染；低于 2K 的屏幕继续由 FIT 等比缩放运行，只在控制台提示。旧 `1280 x 720` UI 按 `2x` 映射，程序化场内对象的世界倍率为 `1.6x`。
- 当前唯一运行时标题图为 `backgrounds/intro/intro-title-background.png`，以 Cover 加安全出血铺满 2K 画布并带轻微分层视差。点击开始后播放 `intro.mp4`，播放完进入教学；教学结束后播放 `tutorial-complete.mp4`，自然播完或按 `Space` 跳过后进入第一关入场。两段视频均可用 `Space` 跳过。
- `src/game/assetManifest.ts` 的 core 共 `203` 个 Loader 项：`200` 张图片、两条节拍音效与教学 BGM，合计 `14,320,123` 字节（约 `13.66 MiB`）。仓库现有图片资源文件总数为 `259`（背景 `16`、角色 `192`、环境 `35`、UI `8`、武器 `8`；角色数含预览 GIF）；已停用的教学进度 / 静态底栏、片头视频、延后加载 BGM 和历史候选不计入 core。
- 教学关使用 `bg1.psd` 的无 UI 环境合成作为池塘底图。进入后先隐藏所有 UI 并锁定玩家操作，主角用 `2.8s` 从左侧自动走到画面中间偏左；停下后在角色头顶显示跟随玩家的浅色半透明像素气泡，鼠标左键或 `Quote` 依次推进六句入场台词，长句按气泡宽度自动换行。新增内容会说明按节奏击打、闪避的短暂无敌，以及三个小节加一次闪避的练习目标。
- 教学开始时顶部连段面板与轻攻击、重攻击、Esc 设置、L / R Shift 闪现四张操作卡均改为运行时绘制的浅绿 / 青绿色可爱像素块：厚像素描边、深青文字和青色按钮统一贴合池塘场景。四张操作卡同时出现并常驻，所有文本仍读取当前操作与当前连招数据，不改教学完成逻辑。教学直接复用正式第一关的实时 ComboMeter；累计完成 3 个完整四拍 Pattern 并成功启动 1 次闪避后，玩家操作锁定并依次显示六句能量说明，其中新增“能量会给你的攻击带来加成。”，最后一句推进后直接进入教学结束动画。
- 教学池塘中的展示对象为粉色教学角色：无手持武器，使用 Idle / Run / Roll 三套动作，以正式粉丝速度的 `68%` 追随玩家，每 `16` 拍先死亡退场再翻滚生成；攻击按粉丝 `0.20 次/拍` 的节奏从嘴部发射粉色单发基础泡泡，玩家受击闪光与冲击反馈和第一关一致，并交替显示 Light / Hard 透明特效。角色加入玩家攻击判定与自动瞄准候选，但其死亡不计入正式波次或掉落。
- 教学关使用 `11111.png` 覆盖后的新版池塘底图，隐藏正式 HP、Wave、状态文字、FPV 和旧 PSD 静态状态条，直接显示移到黄框目标位置的第一关 ComboMeter / 武器状态组。正式关恢复完整实时 HUD 与 FPV。教学结束视频后，主角固定朝右，从左侧自动走到屏幕中央，以同款气泡说完两句对白后开始真实 `5s` 倒计时；倒计时攻击不增加 ComboMeter，开波时恢复收益。
- 两把武器各有一套四段轻重连招：任意踩中鼓点的轻攻击起手，后续必须在紧接着的下一拍完成对应步骤，漏拍、错拍或类型错误都会失败。正式顶部节奏条默认隐藏，起手后显示为无底板四图标样式，整体收为 `88%`，图标半径 / 间距同步缩小并整体上移到最新红框目标内，避免遮挡门口下方物件；第二关底部 ComboMeter / 武器组独立改为更短的横向半透明像素条，基础框约 `278 x 42`、整体 `87%`，只覆盖第二关底部红框目标位。第一关底部 ComboMeter / 武器组也使用独立布局，基础框约 `266 x 42`、整体 `87%`，放在最新黄框目标位置。两关的圆心百分比与武器名都继续读取当前运行数据，不写死显示内容。正式 ComboMeter 使用橙色进度弧，圆心显示普通量表或 Fever 剩余时间的实时百分比；玩家 HP 为 `144 x 50` 世界单位的头顶小血条。
- 教学与正式关统一使用闪现能量门槛：踩拍闪现需要并消耗 `10` 点，错拍需要并消耗 `20` 点；当前 ComboMeter 或 Fever 剩余等价能量不足时，闪现不会启动、不会位移也不会清弹。
- 战斗活动区为 `x=96, y=96, 2368 x 1248px`，不可见物理边界仍生效，但教学和正式关均不创建常驻紫色边框、边缘律动色块或底部汇聚节奏条。正确输入仍显示屏幕锚定的短时判定框，起始 Alpha 为 `0.5`；连招已起手时，第 2–4 步恢复旧版同层级的三框小节预告，按原 `0.7x → 1x`、`2.4` 拍指数缩放曲线推进，并按待输入类型着色。正确重拍保留边框粒子，并随机把少量粒子强化为更大、更亮的烟花主束。
- `4/4`，教学关和第一关节奏 BPM 均默认 `132`，可分别在 P Menu 手动输入；背景每拍播放同一种旧荧光棒轻攻击音色的短鼓点，响度为此前 `3x`。攻击判定窗口为拍点前后各 `0.2s`：校准后绝对误差 `≤100ms` 为 `PERFECT`，`100–200ms` 为 `GOOD`，其余、连招步骤轻重类型错误，或下一步拍点后 `200ms` 仍未输入均为连招失败。教学默认 `bgm0.mp3` 实测为 `153.057 BPM / 0.0s` 首拍 / `436` 循环拍，正式关默认 `bgm1.mp3` 为 `145 BPM / 0.0s` 首拍 / `498` 循环拍（军鼓频段八段相位检验，见 scripts/measure_audio_timing.py）；每关 BGM 按该关目标 BPM 与源 BPM 的比例变速；BGM 基础混音为 `0.125`。
- `Esc` 设置只保留当前实际发声的三路：主音量、BGM、节拍与轻重喊声，默认均为 `100%`、范围 `0–200%`；三条滑杆等距排列，FPV 开关上移到其下方。打开设置或 P 面板时，节拍、BGM、物理、动画、补间与玩法输入全部暂停。
- `P` 面板包含“速度 / 频率、玩家伤害、量表 / Fever、敌人 / 掉落、Boss、模式 / 导出”六页。玩家移动速度默认 `260 px/s`，可在“速度 / 频率”页调节并随配置保存 / 导出；“模式 / 导出”页可切换自动 / 手动瞄准。“量表 / Fever”页除 Perfect `4` 点、Good `3` 点和完整 Pattern `10` 点奖励外，可分别设置教学关 / 第一关节奏 BPM：默认均为 `132`，范围 `40–240`，`±` 步进 `0.1`，点击蓝色数值可直接键盘输入小数；关闭 P Menu 后，Conductor、判定节拍和当前 BGM 播放速度按新值重新对齐。同页还包含默认 `1.0 点/秒` 的 ComboMeter 自然衰减，以及范围 `-500–500ms`、步进 `5ms` 的正式关节拍对齐偏移。全部 BPM 数值随 P Menu 配置保存，并导出到 TXT 的 `[bgm]` 段。
- 荧光棒轻击、普通重击和贯屏重击均不施加击退。警棍四拍 Pattern 为“轻击 → 重击按下 → 重击松开 → 轻击”；保持重击期间持续发射当前弧形光波，默认 `4.0 次/秒`。警棍左右键的覆盖角均按 ComboMeter 档位以 `100% / 125% / 150%` 扩大，右键扫击 / 月牙波的击退分别强化为 `360 / 480 px/s`。
- 所有敌方子弹不再按拍数或固定飞行距离自动销毁；普通点弹、Boss 三连弹、半月波和音符弹阵都会持续飞行，直到命中、被清弹效果清除或场景重置。前五波普通敌人总数为 `2 / 6 / 12 / 18 / 24`，均按 P Menu 的批次规则生成；第五波后进入警卫长 Boss 战。清空 Boss 与随从后显示 `VICTORY`，立即停止玩家、残留特效、物理、动画、节拍和音频，不再生成后续波次，按 `R` 可重新开始。
- 正式保安与粉丝的 Idle / Run 已替换为场景统一配色，玩家轻击、两类 NPC 轻 / 重攻击特效已替换为修复透明通道的序列。正式保安接入 Idle / Run 各 8 帧及独立警棍，整体相较此前显示比例放大 `1.25x`；警棍再放大 `1.25x`，维持素材原色、无 Tint / Bloom，攻击时完成 `200ms` 挥击。玩家移动中使用警棍攻击不会锁住跑步动画。玩家线弹与保安 / 粉丝水滴弹现在分别把近白核心、明亮过渡、饱和实色外壳和极窄柔光烘入单张运行时 CanvasTexture，并且每颗弹只显示一个 `NORMAL` Image，不再叠加独立 ADD 光层；敌方水滴弹会随弹道旋转，小尾端朝发射者，大圆头朝飞行方向 / 被攻击者，颜色与亮度沿用既有青色、橙红和粉色方案。警棍、重击、Fever / 冲刺音波和清屏条也使用实色主体配克制外沿光。命中反馈改为保留纹理的暖粉短闪，致死帧不再出现放大纯白剪影。玩家红色线弹的可见主体在该材质基础上再缩短 `20%`，由判定段 `1.35x` 收为 `1.08x`，尾端锚点、外部纹理包围、厚度、判定、动画、速度、寿命、伤害和命中盒均不变。
- 敌人被击败时，在死亡位置触发一次性爆炸：双层冲击环、放射状长条溅射、主爆炸粒子和高速火花；保安为青色系、粉丝为橙红色系，短暂扩散后自动销毁，不依赖新素材或常驻动画。
- 玩家、正式粉丝、正式保安和教学角色均使用 `256 x 256px` 同画布阴影，运行时 Alpha 为 `0.45`；阴影不参与角色拍点缩放，层级仅高于场景并低于攻击特效、武器和角色。角色、武器和特效继续按脚底 Y 与所属角色深度排序；掉落武器的外环加粗、扩大并提高 Glow，武器贴图自身也增加独立发光，拍点时亮度更明显。正式关底图与非白名单环境物件保持静止，仅 `5、9、17、18、19、22、25–34、36` 这 17 个红框确认物件随轻 / 重拍回弹并生成顶部粒子花。主镜头基础 zoom 为 `1.065x`，死区为活动区 `3%`，最大前探约 `45 / 30px`，以约 `220ms` 阻尼缓入缓出；攻击、命中、Combo、Fever 和错误反馈不再触发整屏 shake 或 zoom punch。
- 教学与正式关 ComboMeter 满格时都会进入 Fever，橙金发光条用 `760ms` 从左向右扫屏并逐列清除敌弹。正确攻击的单发 / 单段伤害为当前武器轻重基础伤害 × 判定倍率 × ComboMeter 倍率；保安掉落警棍、粉丝掉落荧光棒，且只有场上没有同种武器时才判定掉落。

精确玩法数值与验证范围见 [简化玩法策划案](docs/简化玩法策划案（原型版）.md)。
