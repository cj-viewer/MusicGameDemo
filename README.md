# MusicGameDemo

基于 **Phaser 4 + Vite + TypeScript** 的 2D 音乐弹幕游戏原型。当前原型验证“自由走位 + 统一鼓点 + 任意拍起手的轻重连招 + 节拍弹幕”的战斗循环。

- 在线试玩：[cj-viewer.github.io/MusicGameDemo](https://cj-viewer.github.io/MusicGameDemo/)
- 开发分支：`dev-1.0`
- 生产 Pages：发布源为 `gh-pages` 分支；推送 `main` 后由 GitHub Actions 自动构建并更新该分支，`dev-1.0` 可通过 Actions 手动部署到同一在线链接。

## 快速开始

```powershell
git clone --branch dev-1.0 https://github.com/cj-viewer/MusicGameDemo.git
Set-Location MusicGameDemo
npm ci
npm run dev
```

默认访问 <http://localhost:5173>；点击画面开始游戏并解锁浏览器音频。端口被占用时可指定其他端口，例如：

```powershell
npm run dev -- --host 127.0.0.1 --port 3000
```

| 指令 | 用途 |
|---|---|
| `npm ci` | 按锁定文件安装依赖 |
| `npm run dev` | 启动带热更新的开发服务器 |
| `npm run build` | TypeScript 检查并构建到 `dist/` |
| `npm run preview` | 本地预览生产构建 |

## 操作

| 输入 | 行为 |
|---|---|
| `W A S D` | 带惯性的八向移动 |
| 自动瞄准 | 默认锁定综合优先级最高的敌人；移动方向前方总角度 `45°` 的扇区内，敌人的有效距离减半，因此实际距离为普通目标 `2 倍` 时仍同等优先 |
| 鼠标左键 / `"` 键 | 轻攻击（需踩节拍） |
| 鼠标右键 / `Enter` | 重攻击（需踩节拍） |
| 左 `Shift` / 右 `Shift` | 沿当前移动方向闪避 |
| `Esc` | 打开 / 关闭浅色磨砂白线音量面板；打开时游戏完全暂停，可调九路音量并开关右下 FPV 观察窗；P 面板打开时按 Esc 会直接切换到音量面板 |
| 左摇杆 | 移动；右摇杆不再控制瞄准 |
| `LB` / `RB` | 闪避 / 自动提交当前连招所需输入（空闲时始终为轻攻击起手） |
| `R` / `F` | 重新开始 / 调试时直接充满 ComboMeter |
| `C` | 调试时直接触发从左向右的全屏发光条清弹效果 |
| `P` | 打开四页调参面板；可调整玩家 / 敌人战斗参数、切换两种重击模式，并一键导出当前战斗参数 TXT |
| `Space` | 在开场标题页或任一段开场视频期间跳过全部片头并进入教学；教学期间直接进入正式关 |

## 当前原型快照

- 内部画布统一为 `2560 x 1440`（2K），Phaser 使用 Nearest Neighbor、`pixelArt` 与整数像素渲染；低于 2K 的屏幕继续由 FIT 等比缩放运行，只在控制台提示。旧 `1280 x 720` UI 按 `2x` 映射，程序化场内对象的世界倍率为 `1.6x`。
- 当前唯一运行时标题图为 `backgrounds/intro/intro-title-background.png`，以 Cover 加安全出血铺满 2K 画布并带轻微分层视差。开始按钮沿用源设计坐标 `ui(1060,230)`，实际中心为 `(2120,460)`、尺寸 `440 x 120`。`backgrounds/title/main-menu.png` 仅作为未加载的上游历史候选保留。点击开始后依次播放 `intro.mp4`、`intro-rocket.mp4`；标题页或视频期间按 `Space` 可跳过全部片头。
- `src/game/assetManifest.ts` 的 core 共 `164` 个 Loader 项：`161` 张图片、两条节拍音效与教学 BGM，合计 `13,357,393` 字节（约 `12.74 MiB`）。仓库现有图片资源文件总数为 `218`（背景 `16`、角色 `151`、环境 `35`、UI `8`、武器 `8`；角色数含预览 GIF）；片头视频、延后加载 BGM 和未被 manifest 引用的历史候选不计入 core。
- 教学关使用 `bg1.psd` 的无 UI 环境合成作为池塘底图；连段面板、进度面板、静态底栏、石子和四条操作卡均为独立透明 UI，并按源 PSD 的 `1920 x 1080` 布局统一乘 `4/3` 显示到 2K。绘制顺序为进度面板 → 静态底栏 → 石子 → 操作卡，因此底部石子位于白线底栏上方。正式关由运行底图与 35 张透明环境物件重组；物件以底边为锚按轻 / 重拍回弹，并在顶部绘制同节拍的小型橙白粒子花。
- 教学中只显示当前一张操作卡，依次为“左键 轻攻击 → 右键 重攻击 → Esc 设置 → L / R Shift 冲刺”；必须实际完成对应操作才推进，乱序输入不提前推进。每张卡从开始淡入起即记为本页面会话已展示，重练或 `R` 重开不会重复出现，完整刷新页面才重置。完成三套完整连招后以轻攻击进入正式关、重攻击重练，`Space` 可直接跳过教学。
- 教学关隐藏实时 gameplay HUD 与 FPV，只显示 PSD 静态状态条；正式关恢复实时 HUD 与 FPV。两把武器各有一套四段轻重连招：任意踩中鼓点的轻攻击起手，后续必须在紧接着的下一拍完成对应步骤，漏拍、错拍或类型错误都会失败，不再绑定全局小节拍位。正式顶部节奏条默认隐藏；起手后显示为 `7aae97b` 的无底板四图标样式，整体由 `58%` 放大到 `116%`，正确输入短闪对应图标，完成或出错即隐藏，出错前会红闪并抖动。底部 ComboMeter / 武器组同步由 `72%` 放大到 `144%`，中心不变，最终约为 `(925,1302,530,144)`；旧左上 HP 已改成 `144 x 50` 世界单位的小血条并固定在玩家原点上方 `80px`，随玩家和镜头移动。教学 PSD HUD 不受影响。
- 战斗活动区为 `x=96, y=96, 2368 x 1248px`，不可见物理边界仍生效，但教学和正式关均不创建常驻紫色边框、边缘律动色块或底部汇聚节奏条。正确输入仍显示屏幕锚定的短时判定框，起始 Alpha 为 `0.5`；连招已起手时，第 2–4 步恢复旧版同层级的三框小节预告，按原 `0.7x → 1x`、`2.4` 拍指数缩放曲线推进，并按待输入类型着色。正确重拍保留边框粒子，并随机把少量粒子强化为更大、更亮的烟花主束。
- `132 BPM`、`4/4`，背景每拍播放同一种旧荧光棒轻攻击音色的短鼓点，响度为此前 `3x`；攻击判定窗口为拍点前后各 `0.2s`：校准后绝对误差 `≤100ms` 为 `PERFECT`，`100–200ms` 为 `GOOD`，其余、连招步骤轻重类型错误，或下一步拍点后 `200ms` 仍未输入均为连招失败。只有连招内正确踩拍才播放裁至峰值前短起声的轻/重“嘿”。除 BGM、背景鼓点和这两种正确输入“嘿”外，场景不再播放其他音效。四首 BGM 按 `132 / 源 BPM` 同步缩放播放速度和首拍偏移；教学默认 `bgm0.mp3`，正式关默认 `bgm2.mp3`，BGM 基础混音为 `0.125`。
- `Esc` 设置有主音量、BGM、六类 SFX 和独立敌人死亡音共九路：前八路默认 `100%`、范围 `0–200%`，敌人死亡音默认及上限均为 `100%`。面板先抓取背后画面，再应用 `blur(14px) saturate(82%) brightness(106%)`、`#f2f0e8 / 0.18` 浅雾与白色轻渐变，不使用深色全屏暗罩；中文标签按定稿显示。打开设置或 P 面板时，节拍、BGM、物理、动画、补间与玩法输入全部暂停。
- `P` 面板包含“速度 / 频率、玩家伤害、敌人 / 掉落、模式 / 导出”四页。默认玩家伤害为荧光棒 `10 / 18`、警棍 `12 / 26`，判定倍率为 `1.2 / 1.0 / 0.5`；荧光棒弹速 `360`、保安 / 粉丝弹速 `144 px/s`，两敌攻击频率为 `1 / 0.25 次/拍`，敌弹伤害均为 `12`，掉落均为 `100%`。无限射程、荧光棒贯屏激光与警棍击退月牙波默认开启；参数 TXT 使用稳定键名且不包含 BGM 槽或 FPV 等纯显示设置。
- 前五波敌人总数为 `2 / 6 / 12 / 18 / 24`。第一波为一粉丝一保安；第二、三波分别为 `2 / 4` 组三人编队（中央粉丝、两侧保安）；第四、五波分别为 `9 / 12` 组一粉丝一保安的配对编队。清空第五波后每隔 `2s` 继续重复 24 敌人的第五波并累计 Wave 编号。粉丝每次攻击默认 `10%` 概率发射三弧共 30 个点弹，否则单发；敌弹节拍突进默认关闭。
- 正式保安接入 Idle / Run 各 8 帧及独立警棍，整体相较此前显示比例放大 `1.25x`；警棍再放大 `1.25x`，维持素材原色、无 Tint / Bloom，攻击时完成 `200ms` 挥击。玩家移动中使用警棍攻击不会锁住跑步动画。玩家线弹与保安 / 粉丝点弹现在分别把近白核心、明亮过渡、饱和实色外壳和极窄柔光烘入单张运行时 CanvasTexture，并且每颗弹只显示一个 `NORMAL` Image，不再叠加独立 ADD 光层；警棍、重击、Fever / 冲刺音波和清屏条也使用实色主体配克制外沿光。命中反馈改为保留纹理的暖粉短闪，致死帧不再出现放大纯白剪影。玩家红色线弹的可见主体在该材质基础上再缩短 `20%`，由判定段 `1.35x` 收为 `1.08x`，尾端锚点、外部纹理包围、厚度、判定、动画、速度、寿命、伤害和命中盒均不变。
- 玩家、敌人、武器和特效按脚底 Y 与所属角色深度排序；正式环境底图为 depth `-20`、正确判定框为 `-19`、35 个环境物件为 `-18` 至 `-17.5`。主镜头基础 zoom 为 `1.065x`，死区为活动区 `3%`，最大前探约 `45 / 30px`，以约 `220ms` 阻尼缓入缓出；四拍图案、Wave、ComboMeter / 武器、面板和 FPV 保持屏幕锚定，玩家头顶 HP 是玩家正式 HUD 中唯一使用世界坐标的组件。
- Fever 满格时，橙金发光条用 `620ms` 从左向右扫屏并逐列清除敌弹；`C` 可调试同一效果。正确攻击的单发 / 单段伤害为当前武器轻重基础伤害 × 判定倍率 × ComboMeter 倍率；保安掉落警棍、粉丝掉落荧光棒，且只有场上没有同种武器时才判定掉落。

精确玩法数值与验证范围见 [简化玩法策划案](docs/简化玩法策划案（原型版）.md)。

**任何影响玩法、参数、素材、输入、音效、表现、工程入口或部署的改动，必须在同一提交中：**

1. 在 `docs/更新记录/` 新增或更新对应日期的短记录；
2. 更新 `docs/实机落地与调整记录.md` 的“当前实机规则”和验收项；
3. 若玩家可感知规则变化，再同步更新简化玩法策划案；
4. 若改变了长期产品目标，再同步完整策划案。

只改代码、不更新文档，视为改动未完成。

## 项目结构

```text
src/                       游戏代码（场景、敌人、玩家、节拍、HUD、武器）
public/assets/             运行时资源
docs/                      项目文档、更新记录和策划附件
.github/workflows/         GitHub Pages 部署工作流
.claude/skills/            Claude 侧 Phaser 技能
.agents/skills/            共享 agent 技能副本
```

`dist/`、`node_modules/` 和本地自动化产物不应提交。资源放置与命名要求见 [资源与素材规范](docs/资源与素材规范.md)。
