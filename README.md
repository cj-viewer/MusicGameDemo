# MusicGameDemo

基于 **Phaser 4 + Vite + TypeScript** 的 2D 音乐弹幕游戏原型。当前原型验证“自由走位 + 固定节拍攻击 + 轻重连段 + 节拍弹幕”的战斗循环。

- 在线试玩：[cj-viewer.github.io/MusicGameDemo](https://cj-viewer.github.io/MusicGameDemo/)
- 开发分支：`dev-1.0`
- 生产 Pages：推送 `main` 自动部署；`dev-1.0` 可通过 GitHub Actions 手动部署。

## 快速开始

```powershell
git clone --branch dev-1.0 https://github.com/cj-viewer/MusicGameDemo.git
Set-Location MusicGameDemo
npm ci
npm run dev
```

默认访问 <http://localhost:5173>；点击画面开始游戏并解锁浏览器音频。端口被占用时可指定其他端口，例如：

```powershell
npm run dev -- --host 127.0.0.1 --port 3000
```

| 指令 | 用途 |
|---|---|
| `npm ci` | 按锁定文件安装依赖 |
| `npm run dev` | 启动带热更新的开发服务器 |
| `npm run build` | TypeScript 检查并构建到 `dist/` |
| `npm run preview` | 本地预览生产构建 |

## 操作

| 输入 | 行为 |
|---|---|
| `W A S D` | 带惯性的八向移动 |
| 鼠标 | 瞄准；前方 `90°` 内自动辅助瞄准最近敌人 |
| 鼠标左键 / 右键 | 轻攻击 / 重攻击（均需踩节拍） |
| `Shift` | 沿当前移动方向闪避 |
| `Alt` | 呼出鼠标并打开主音量滑块；再次按 `Alt` 或按 `Esc` 关闭 |
| 左 / 右摇杆 | 移动 / 瞄准 |
| `LB` / `RB` | 闪避 / 自动按当前节拍提交轻或重攻击 |
| `R` / `F` | 重新开始 / 调试时直接充满 ComboMeter |

## 当前原型快照

- `146.32 BPM`、`4/4`；攻击判定窗口为拍点前后各 `0.1s`。`bgm3.mp3` 的首拍偏移为文件内 `0.026s`，启动及每 616 拍循环时都与节拍时钟重新对齐。
- 默认主音量为 `150%`，`Alt` 可呼出鼠标并在 `0–300%` 范围内调整；BGM 基础音量为 `0.3`，轻、重节拍叫喊基础音量均为 `0.28`，程序合成音效也统一经过主音量。素材分别提前 `70ms / 74ms` 播放，重叫喊在素材时间 `330–360ms` 淡出。
- 战斗区为 `1092 x 614px`，相对屏幕左、右、下各预留约 `82px` 的人群律动带。约 140 根完全不透明的深紫粉竖条沿三侧随机重叠放置，宽度由上一版缩为约 `0.8x`（`22–26px`）、高度约 `42–58px`。律动条没有碰撞盒，可在跳动时侵入战斗区；轻重拍的明度提升和饱和度降低均不超过 `5%`。
- 律动条与角色 Sprite / Image 统一按脚底 Y 做 TopDown 遮挡：越靠屏幕下方越晚绘制并遮住上方对象；玩家手持武器、瞄准线和敌人血条跟随所属角色深度。
- 左上 HP 血条加入同拍律动：轻拍前纵向压至 `0.9x`、拍点弹至 `1.15x`；重拍前压至 `0.72x`、拍点弹至 `1.32x`。只改变厚度和最多 `5%` 的明度 / 饱和度，血量长度与数字保持稳定。
- 战斗区内角色、碰撞体、手持武器、掉落、敌我弹幕和对应场内特效统一缩放至上一版的 `0.8x`；HUD、场地、节奏条与边缘律动带不缩放。圆形表盘标题常驻显示 `ComboMeter`。
- 节奏条预览未来 `3` 拍，相邻节拍间距 `120px`，从两侧以约 `293px/s` 汇聚到中心判定点。
- 手持武器绑定在角色手部锚点，随朝向换手：荧光棒双棒同握一手呈扇形前倾，警棍同手前倾持握；每次挥击围绕手部在 `200ms` 内完成，不再延续到下一拍。荧光棒弹幕速度为 `360 px/s`。
- 五波敌人总数为 `2 / 4 / 8 / 16 / 32`，每波保安与粉丝各半。
- 玩家使用像素女高中生序列帧（Dlou Saiyan 素材，非商用需署名）：待机 2 帧、跑步 4 帧、倒地 1 帧，可见高度约 `63.6px`，瞄准左侧时翻转并随节拍轻微蹲弹；粉丝使用序列帧：慢行跑步 `02–05`，拍前突进和受击使用翻滚，按小节攻击时使用近战。素材默认朝右，向左时由引擎翻转。
- 粉丝动作保持旧静态粉丝的动作占比并统一乘 `0.8x`：跑步、翻滚、近战可见高度约 `58.4 / 54.4 / 65.6px`；同一动作内帧高一致、宽度等比变化。粉丝拍间慢行 `30 px/s`，下一拍前 `0.1s` 的翻滚突进按约两倍旧位移调校。

精确玩法数值与验证范围见 [简化玩法策划案](docs/简化玩法策划案（原型版）.md)。

## 文档入口与维护规则

文档目录的职责和更新顺序见 [docs/README.md](docs/README.md)。各文件不是重复备份：

| 文档 | 用途 |
|---|---|
| [简化玩法策划案](docs/简化玩法策划案（原型版）.md) | 当前可运行原型的玩家规则与验收范围 |
| [实机落地与调整记录](docs/实机落地与调整记录.md) | 代码事实、精确参数、历史变更和验收清单 |
| [完整策划案](<docs/2D音乐弹幕游戏策划案 (持续更新).md>) | 长期产品目标；不等于已实现内容 |
| [更新记录](docs/更新记录/README.md) | 每次可交付改动的短记录与影响范围 |
| [资源与素材规范](docs/资源与素材规范.md) | 资源目录、命名、加载和验收规则 |
| [AGENTS.md](AGENTS.md) | Agent 进入项目时必须先读的规范、变更合同与验证要求 |

**任何影响玩法、参数、素材、输入、音效、表现、工程入口或部署的改动，必须在同一提交中：**

1. 在 `docs/更新记录/` 新增或更新对应日期的短记录；
2. 更新 `docs/实机落地与调整记录.md` 的“当前实机规则”和验收项；
3. 若玩家可感知规则变化，再同步更新简化玩法策划案；
4. 若改变了长期产品目标，再同步完整策划案。

只改代码、不更新文档，视为改动未完成。

